## 7.1 用一句话说清楚项目

**STM32F103 每 2 秒读一次 DHT11，拼成 JSON，通过 MQTT 协议经 ESP8266 WiFi 模块发到 OneNET 平台。**

数据路径就一条直线——不复杂，但每一层都有各自的坑。

## 7.2 分层的接口长什么样

整个项目最值钱的设计不是"跑通了"，是**层与层之间的接口定义**。
看懂这四张表，你就知道换什么、不动什么。

### 应用层 → 协议层

应用层（`task_wifi.c`）调用 MQTT 层（`mqtt.c`），只用了三个函数：

```c
uint8_t MQTT_Connect(void);                               // 建会话
uint8_t MQTT_Publish(const char *topic, const char *payload);  // 发数据
uint8_t MQTT_Ping(void);                                  // 保活
```

**如果哪天要换 CoAP 或 HTTP**，把这三个函数重新实现一遍，上层代码几乎不动。

### 协议层 → 驱动层

MQTT 层需要两个底层能力：**发字节** 和 **收字节**。

```c
// MQTT 发数据
ESP8266_TCPSend(s_MqttTxBuf, len);

// MQTT 收应答
ESP8266_TCPRecvRaw(rx, sizeof(rx), timeout);
```

**如果哪天 WiFi 模块换成 NB-IoT 或以太网**，只要新驱动的 `TCPSend` / `TCPRecvRaw` 接口不改，
MQTT 层一个字都不用动。

### 驱动层 → 硬件

驱动层通过两个串口跟外面通信：

```
USART1 (PA9/PA10) — 接 USB-TTL，调试输出（printf）
USART2 (PA2/PA3)  — 接 ESP8266，AT 命令 + 数据收发
```

DHT11 走一根 GPIO（PB12），单总线协议。

### 采集 → 通信（任务间）

两个任务不直接调函数，通过队列传递数据：

```c
// 采集任务（生产者）调用
xQueueSend(g_xDht11Queue, &dht, 0);

// 通信任务（消费者）调用
xQueueReceive(g_xDht11Queue, &dht, pdMS_TO_TICKS(30000));
```

**如果以后加光照传感器**：要么另开一条队列，要么定义一个带来源标记的共用数据结构。
详见 `task_light.c` 文件头的说明。

## 7.3 如果我想换个东西，要改哪？

| 想做什么 | 要改的文件 | 改什么 |
|---|---|---|
| **换 WiFi** | `app_config.h` | 改 `CFG_WIFI_SSID` / `CFG_WIFI_PASSWORD` |
| **换云平台** | `app_config.h` + `task_wifi.c:285-290` | 改 MQTT 参数 + JSON 报文模板 |
| **换传感器** | 加 BSP 驱动 + 新建 `task_xxx.c` | 采集逻辑，通信层不用动 |
| **加传感器** | 照抄 `task_dht11.c` 建新任务 | 数据通道二选一（见 `task_light.c`）|
| **换通信模块** | 重新实现 `ESP8266_TCPSend` / `TCPRecvRaw` 等接口 | 协议层不用动 |
| **改上报频率** | `app_main.h` | 改 `APP_DHT11_PERIOD_MS` |
| **改任务栈大小** | `app_main.h` | 改 `APP_STACK_WIFI` / `APP_STACK_DHT11` |

**原则：一次只动一层。**

## 7.4 你学会了什么

### 硬技能

1. **C 语言裸机编程**：GPIO 操作、UART 通信、定时器/DMA/DWT 的用法
2. **FreeRTOS 实时操作系统**：任务创建、优先级、队列、栈/堆管理
3. **ESP8266 AT 指令集**：模块初始化、WiFi 关联、TCP 连接、数据收发
4. **MQTT 协议（3.1.1）**：CONNECT / PUBLISH / PINGREQ 报文结构、剩余长度编码、QoS 0
5. **MQTTX 调试工具**：在 PC 端独立验证 MQTT 凭据
6. **OneNET 平台操作**：创建产品、物模型定义、Token 鉴权、查看数据点
7. **DHT11 单总线时序**：起始信号、应答、40bit 位流、校验和
8. **DMA 环形缓冲区**：利用 CNDTR 轮询实现非阻塞串口接收
9. **弱符号机制（`__weak`）**：驱动层不依赖 RTOS，但 RTOS 下能自动切换延时策略

### 软技能（比硬技能更值钱）

1. **分层排查**：哪一层出了问题，用那一层的成功标志来确认——不要跳步
2. **二分排除法**：把同一串凭据拿到 PC 端复现，一次排除"设备 + 代码 + 硬件"
3. **不相信报错字面意思**：`code 4` 不是密码错、`SEND OK` 不代表平台收到了、扫得到热点不等于连得上
4. **只认最终结果**：控制台上出现数据点才是"成功"的唯一标准
5. **读代码里的注释**：前人把坑写在了注释里，改代码之前先看文件头的说明

## 7.5 可能的方向

这个项目是做完了，但**不是做完了就扔在那里**。可以继续玩的方向：

| 方向 | 复杂度 | 改动量 |
|---|---|---|
| **加光照传感器（BH1750）** | 低 | 照抄 `task_dht11.c`，见 `task_light.c` 的步骤说明 |
| **加 OLED 显示当前温湿度** | 中 | I2C 驱动 OLED + 一个新任务从队列取数据显示 |
| **换成 TLS 加密** | 高 | `AT+CIPSTART="SSL",...`，12888 端口，**注意 ESP8266 内存是否够** |
| **加 MQTT 订阅收指令** | 中 | 实现 SUBSCRIBE 报文 + 改造 `TCPRecvRaw` 的处理逻辑 |
| **接入 Home Assistant** | 中 | 改 MQTT 主题为 Home Assistant 的 auto-discovery 格式 |
| **低功耗（电池供电）** | 高 | 休眠模式 + RTC 定时唤醒 + 降低上报频率 |

**每次只加一个东西，加一个验证一个。** 不要一次改完再试——那样出了问题
你又不知道是哪一层的问题了。
