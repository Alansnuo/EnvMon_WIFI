# ③ ESP8266 WiFi 模块驱动 —— 从"AT"到"连上云"

> 适用人群：第一次用 ESP8266 / 不知道"AT 指令"是什么 / 
> 想知道代码是怎么和模块对话的
>
> 读完本篇你会知道：ESP8266 是什么、怎么跟它"说话"、
> 代码里的每一层分别做了什么。

---

## 3.1 ESP8266 是个什么"模块"

**ESP8266 是一个自带 CPU 和 WiFi 的小芯片。** 它自己跑了一套 AT 固件，
你通过串口发文本命令给它，它帮你做 WiFi 的事情。

```
你（STM32）                      ESP8266
─────────                       ────────
"AT\r\n"                    →    "OK"
"AT+CWMODE=1\r\n"           →    "OK"
"AT+CWJAP=...\r\n"          →    "WIFI CONNECTED"
"AT+CIPSTART=...\r\n"       →    "CONNECT"
"\x10\x9C\x01..."           →    "SEND OK"
```

**核心概念：AT 指令 = 文本命令。** 你发一段以 `\r\n` 结尾的 ASCII 文本，
ESP8266 执行后回一段文本。这个对话模式叫"命令-响应"。

整个 ESP8266 驱动做的事，就是**发命令 → 等预期应答 → 超时报错**，
反复循环。

## 3.2 接线（再来一遍）

```
STM32 PA2 (USART2_TX)  ───→  ESP8266 RXD
STM32 PA3 (USART2_RX)  ←───  ESP8266 TXD
STM32 PB1              ───→  ESP8266 RST（复位引脚）
```

注意：**TX 接 RX，RX 接 TX**（交叉）。

供电：ESP8266 需要 **3.3V**，峰值电流能到 300mA。如果你的 3.3V 是
从 STM32 板子上的稳压器取的，要确认够不够 —— 供电塌陷是"模块死了"
最常见的假象。

## 3.3 驱动分几层

ESP8266 的代码在 `BSP/ESP8266/` 下，分三个层次：

```
┌──────────────────────────────────────────────┐
│ 第三层：业务接口                               │
│ ESP8266_Init  ESP8266_ConnectWiFi              │
│ ESP8266_TCPConnect  ESP8266_TCPSend            │
│ 你直接调用的函数都在这里                         │
├──────────────────────────────────────────────┤
│ 第二层：命令层                                  │
│ ESP8266_SendCmd(cmd, expected, timeout)        │
│ "发命令，等应答" 的核心封装                      │
├──────────────────────────────────────────────┤
│ 第一层：收发层                                  │
│ ESP8266_WaitResponse(expected, timeout)         │
│ 从 DMA 环形缓冲区里读字节、搜字符串               │
│ ESP8266_RxStart()  打开 DMA 接收                │
└──────────────────────────────────────────────┘
```

**初次接触不必看懂每一行，抓住 3.4 节那几条命令就够了。**

## 3.4 核心 AT 指令速查

以下是你需要理解的指令（完整的在 `ESP8266_知识点与AT指令.md`）：

| 指令 | 做什么 | 期望应答 |
|---|---|---|
| `AT` | 测试模块是否活着 | `OK` |
| `ATE0` | 关闭回显（不自作多情地把命令重复一遍） | `OK` |
| `AT+CWMODE=1` | 设为 Station 模式（连别人的热点） | `OK` |
| `AT+CWJAP=“SSID”,“密码”` | 连指定热点 | `WIFI CONNECTED`+`OK` |
| `AT+CIPSTART=“TCP”,“域名”,端口` | 建 TCP 连接 | `CONNECT` |
| `AT+CIPSEND=长度` | 告诉模块"我要发 N 字节" | `>` 提示符 |
| （接着发 N 字节数据） | 实际发送 | `SEND OK` |

**ESP8266 就是一串命令接一串命令。** 把上面的流程串起来，就是联网的全过程。

## 3.5 初始化流程（`ESP8266_Init`）

```c
ESP8266_Init()
{
    1. 拉低 RST 引脚 100ms → 释放 → 等 1 秒    // 硬复位模块
    2. 发 "AT\r\n" → 等 "OK"                  // 确认模块活着
    3. 发 "ATE0\r\n" → 等 "OK"                // 关回显
    4. 发 "AT+CWAUTOCONN=0\r\n" → 等 "OK"     // 关后台自动重连
}
```

**为什么关自动重连？** 模块 flash 里存着上次连过的 AP，默认上电就自己往那儿连。
那个 AP 的密码要是改过，它就在后台没完没了地重试，跟我们要发的 `AT+CWJAP`
抢射频状态。所以说：连接由我们全权负责。

**为什么先复位？** 模块跑久了内部状态可能脏了，硬复位是最干净的起点。
注意 `HAL_UART_DMAStop()` 那行（见 3.9）必须在每次复位前调用，否则
第二次初始化时 DMA 还锁着，永远起不来。

## 3.6 连 WiFi（`ESP8266_ConnectWiFi`）

```c
ESP8266_ConnectWiFi(ssid, password)
{
    1. 发 "AT+CWQAP\r\n"               // 断开残留连接（忽略失败）
    2. 发 "AT+CWJAP=\"SSID\",\"PASS\""  // 连目标热点
       → 等 "WIFI CONNECTED" 或 "OK"
}
```

`AT+CWJAP` 可能返回的错误码：
- `+CWJAP:1` — 超时（热点不在范围内）
- `+CWJAP:2` — 密码错误
- `+CWJAP:3` — 找不到目标 AP
- `+CWJAP:4` — 连接失败（**热点拒绝了**，可能是黑名单）

诊断工具：`WifiDiagScan()` 会调用 `AT+CWLAP` 扫描周边热点，用来区分
"热点不在跟前"和"热点在但拒接"。

## 3.7 建 TCP 连接（`ESP8266_TCPConnect`）

```c
ESP8266_TCPConnect(host, port)
{
    1. 发 "AT+CIPMUX=0\r\n"                    // 单连接模式
    2. 发 "AT+CIPSTART=\"TCP\",\"host\",port"  // 建连接
       → 等 "CONNECT"
}
```

**传域名也能用**：虽然参数名叫 `ip`，但 ESP8266 会自己做 DNS 解析。

**注意**：此处连的是 MQTT 服务器的 1883 端口（明文）。TLS 需要另一套指令
（`AT+CIPSTART="SSL",...`），本项目不走那条路。

## 3.8 发数据（`ESP8266_TCPSend`）

这是 AT 固件里少有的"两步式"命令：

```c
ESP8266_TCPSend(data, len)
{
    1. 发 "AT+CIPSEND=%u\r\n"     // 告诉模块"我要发 N 字节"
    2. 等 ">"                     // 模块准备好了，给我数据
    3. 直接用串口发 len 字节       // 你的数据
    4. 等 "SEND OK"               // 模块说发出去了
}
```

**⚠️ 两个重要的"不是"**
- `SEND OK` **不是平台回执**，只是 ESP8266 说"我塞进 TCP 了"
- 平台拒收主题时**不会回任何东西**，直接断掉 TCP
- 所以你看到 `SEND OK` 不说明数据到了平台，只说明本地发出了

## 3.9 一个大坑：`HAL_UART_DMAStop()` 不能省

```c
static ESP8266_Status ESP8266_RxStart(void)
{
    (void)HAL_UART_DMAStop(&ESP8266_UART);   // ← 这一行不能省！
    ...
    HAL_UART_Receive_DMA(...);
}
```

**为什么需要这行？** 因为 `HAL_UART_Receive_DMA()` 要求 `RxState == READY`。
第一次调的时候是 READY，没问题；但第二次进来时（比如重连），DMA 还在环形模式里跑，
`RxState` 还停在 `BUSY_RX`，于是 `Receive_DMA` 直接返回失败，`Init()` 立刻退出。

**症状极其有迷惑性**：第一次失败之后**永远**失败，看起来像模块坏了。

**这就是加了自动重连后必须要有这一行的原因。**

## 3.10 接收数据的机制（DMA 环形缓冲）

本项目不用中断轮询，而是用 **DMA 在后台自动接收**：

```
ESP8266 发数据 → USART2 → DMA → ESP8266_DmaBuf[256]（环形缓冲区）
                                      ↑
                                CPU 轮询 CNDTR 计数器
                                知道写了多少，搬走
```

好处：
- CPU 不用守着串口，该干啥干啥
- 关中断那 4ms 里来的字节也落得进去（DMA 是硬件干的事）

**环形缓冲区里的字节有两条去路**，而且**互相看不见对方**：

```
                                 ┌──→ ESP8266_WaitResponse()
                                 │     搬进 RxBuf，用 strstr 搜 AT 文本应答
DMA → DmaBuf[256]（环形） ───────┤
                                 └──→ ESP8266_TCPRecvRaw()
                                       直接取走，剥掉 +IPD,<len>: 前缀
                                       MQTT 层收 CONNACK / PINGRESP 走这条
```

- `ESP8266_TCPRecvRaw()` 里的 **`+IPD` 剥离状态机已经实现了**（`esp8266.c:605`），
  它连"头部被切成两半"的情况都处理了。这是 `ESP8266_TCPReceive()` 那个旧函数
  的替代品，接口也从"返回状态码"改成了"返回收到的字节数"。
- **仍然成立的风险只剩一条**：在等 AT 应答的那段时间里，如果服务器主动推数据
  过来（订阅推送），那份数据会被 `WaitResponse` 卷进 `RxBuf` 当文本搜掉。
  本项目只上报、不订阅，所以现在触发不了；**将来要做 MQTT 订阅，必须先改这里**。

> 这套接收架构的逐行原理见 [详解/02-ESP8266接收架构与+IPD剥离](09-ESP8266接收架构与+IPD剥离.md)。

## 3.11 重连是怎么做到的

`WifiConnect()` 里失败了怎么办？回到上层（`TaskWifi`）的外层循环：

```c
for (;;)
{
    while (WifiConnect() == 0)          // 连不上就一直重试
    {
        vTaskDelay(5000);               // 等 5 秒
    }
    
    while (failStreak < 3)              // 连上了，开始上报
    {
        ...上报...
        if (失败) failStreak++;
        else      failStreak = 0;
    }
    // 连续失败 3 次 → 跳出内层 → 回到外层重连
}
```

注意：重连 = 重新调 `ESP8266_Init()` → 里面的 `ESP8266_Reset()` 会拉 RST 引脚
**硬复位模块**。模块卡死、socket 半开、WiFi 掉了，走一遍都能回到干净状态。
代价是每次重连多花约 2 秒。

同时重连期间：**采集不会停**，因为 `TaskDht11` 是独立任务。
