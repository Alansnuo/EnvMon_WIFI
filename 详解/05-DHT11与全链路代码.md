## 5.1 DHT11 是什么

DHT11 是一个**单总线数字温湿度传感器**。它用一根线跟单片机通信，
数据格式：

```
40 bit = 湿度整数(8) + 湿度小数(8) + 温度整数(8) + 温度小数(8) + 校验和(8)
         (本项目小数部分未用，因为 DHT11 测到的小数永远是 0)
```

数据引脚需要**4.7k~10k 上拉电阻**（一般买 DHT11 模块已经带了）。

## 5.2 DHT11 时序（知道就行）

DHT11 的通信是**主机主动发起**，从机回应的模式：

```
主机:  拉低 20ms → 释放（拉高）→ 等 20~40us
从机:  回 80us 低 + 80us 高（应答信号）
数据:  每 bit 先 50us 低，然后：
          26~28us 高 = 0
          70us 高    = 1
```

**为什么强调这些？** 不是要你背，而是告诉你：

1. 整个过程约 4ms 内不能打断（关了中断的），否则时序不准
2. 判 0/1 靠的是**测量高电平宽度**：>45us 判 1，<=45us 判 0
3. 两次读取间隔必须 >= 1 秒（DHT11 自己的限制）

## 5.3 DHT11 驱动结构（`BSP/DHT11/dht11.c`）

两个函数就够了：

```c
uint8_t DHT11_Init(void);    // 初始化时基 + 拉高总线空闲
uint8_t DHT11_Read(DHT11_Data *data);  // 读一次，返回 1=成功
```

`DHT11_Read` 内部：关中断 → 收发 40bit 位流 → 开中断 → 校验和检查

**需要注意的是**：
- 初始化里的 `BSP_DelayMs(1000)` 是在 `App_Init()` 里跑的（调度器启动前），
  那时候没有别的任务，阻塞 1 秒没关系
- 驱动里的 `BSP_DelayMs` 在调度器跑起来后会自动变成"挂起本任务"，
  不会忙等——这是 `bsp_delay.h` 的 `__weak` 机制实现的
- 时基用的是 DWT（Cortex-M3 自带的周期计数器），不是 SysTick，
  因为 FreeRTOS 占了 SysTick 做 tick

## 5.4 采集任务（`APP/task_dht11.c`）

采集任务的职责非常单一：

```c
static void TaskDht11(void *argument)
{
    DHT11_Data dht;
    uint32_t   count = 0;
    
    for (;;)
    {
        if (DHT11_Read(&dht))                      // 读传感器
        {
            count++;
            printf("[DHT11] #%lu  Temp: %d C  Humi: %d%%\r\n",
                   (unsigned long)count, dht.temperature, dht.humidity);
            
            if (xQueueSend(g_xDht11Queue, &dht, 0) != pdPASS)
            {
                printf("[DHT11] queue full, sample dropped\r\n");
            }                                      // 超时=0: 满了就丢新的
        }
        vTaskDelay(pdMS_TO_TICKS(APP_DHT11_PERIOD_MS));  // 睡 2 秒
    }
}
```

**边界**：
- 读完就睡，绝不碰网络
- 队列满了就丢，绝不阻塞
- 不需要知道数据去哪了

## 5.5 队列（`APP/app_main.c`）

队列是连接两个任务的桥梁：

```c
// app_main.c
g_xDht11Queue = xQueueCreate(APP_DHT11_QUEUE_LEN, sizeof(DHT11_Data));
// 队列长度 = 4，每个元素 = sizeof(DHT11_Data) = 2 字节（两个 uint8_t）
// 最多囤 4 次采样，满了**丢掉新来的那次** —— 是丢新的，不是覆盖旧的
```

采集任务往队列**放**，通信任务从队列**取**：

```
TaskDht11                    TaskWifi
  xQueueSend()                 xQueueReceive()
    ├── 队列满了 → 丢掉          ├── 有数据 → 立刻返回
    └── 没满   → 放入          └── 没数据 → 等 30 秒
```

## 5.6 通信任务（`APP/task_wifi.c`）

通信任务做的事情最多，分两个阶段。

### 阶段 1：联网

```c
while (WifiConnect() == 0)    // 连不上就一直重试
{
    vTaskDelay(5000);
}
```

`WifiConnect()` 按顺序做六件事：
1. `ESP8266_Init()` — 复位模块、ATE0、CWAUTOCONN=0
2. `ESP8266_SetWiFiMode(STA)` — 设为 Station 模式
3. `ESP8266_ConnectWiFi(ssid, pass)` — 连热点
4. `ESP8266_GetIPAddress()` — 取本机 IP（**只是为了打印**）
5. `ESP8266_TCPConnect(host, port)` — 建 TCP 连到 OneNET
6. `MQTT_Connect()` — 发 MQTT CONNECT 报文

**前一步失败，后一步根本不执行** —— 只有一个例外：**第 4 步失败了不返回**。
拿不到 IP 说明不了什么，也不影响后面采集，所以只打印一句就继续。

第 3 步失败时会把模块的原始应答打出来，再调 `WifiDiagScan()` 扫一遍周边热点 ——
用来把"热点不在跟前"和"热点在但拒绝了你"分开。

### 阶段 2：上报循环

```c
failStreak = 0;
while (failStreak < 3)
{
    if (xQueueReceive(...))           // 队列有数据？
    {
        snprintf(payload, ...);       // 拼 JSON
        if (MQTT_Publish(topic, payload))
        {
            failStreak = 0;           // 成功 → 归零
        }
        else
        {
            failStreak++;             // 失败 → 累加
        }
    }
    else
    {
        // 30 秒没数据 → 发心跳
        if (MQTT_Ping()) failStreak = 0;
        else             failStreak++;
    }
}
// 连续失败 3 次 → 回到阶段 1（重连）
```

## 5.7 JSON 报文怎么拼的

上报到 OneNET 物模型的数据必须是这个格式：

```json
{"id":"1","version":"1.0","params":{"Temp":{"value":27.0},"Hum":{"value":98.0}}}
```

代码里：

```c
(void)snprintf(payload, sizeof(payload),
    "{\"id\":\"%lu\",\"version\":\"1.0\",\"params\":{"
        "\"Temp\":{\"value\":%d.0},"
        "\"Hum\":{\"value\":%d.0}"
    "}}",
    (unsigned long)(++msgId),
    dht.temperature,
    dht.humidity);
```

**细节**：
- 属性名 `Temp` / `Hum` 是首字母大写，跟控制台"功能定义"一致
- 值写成了 `%d.0`（比如 `27.0`）而不是 `%d`，因为属性类型是浮点
- `"id"` 用自增计数器，不是固定 `"1"`——OneNET 靠它去重
- `\"` 是 C 语言里的转义，实际发出去的是双引号

## 5.8 启动入口（`APP/app_main.c`）

```c
void App_Init(void)
{
    DHT11_Init();                    // 1. 传感器初始化（调度器还没开）
    printf("DHT11 Sensor Ready!\r\n");
    
    g_xDht11Queue = xQueueCreate(...);  // 2. 建队列
    
    TaskWifiCreate();                // 3. 建 WiFi 任务
    TaskDht11Create();               // 4. 建 DHT11 任务
}
```

然后就交由 FreeRTOS 调度器分配时间片了。
