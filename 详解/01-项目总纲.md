# ① 项目总纲 —— 你到底在做一件什么事

> 适用人群：零基础 / 刚接触嵌入式 / 不知道这个项目是干什么的
>
> 读完本篇你会知道：这个项目做什么、用了什么硬件、软件分几层、
> 数据是怎么从传感器一路飞到你手机上的。

---

## 1.1 项目做什么

**一句话**：用 STM32F103C8 读温湿度（DHT11），通过 ESP8266 WiFi 模块
连上 OneNET 云平台，在平台上看到实时数据。

**长一点**：设备每 2 秒测一次温度和湿度，把数据打包成 JSON 格式，
通过 MQTT 协议（物联网最常用的通信协议）发到中移物联网的 OneNET 平台。
你在浏览器或手机上登录 OneNET 控制台，就能看到实时的温湿度曲线。
如果 WiFi 断了，设备会自动重连。

你可以把它理解成一个"自己做的气象站"发布到互联网上。

## 1.2 用了哪些硬件

| 零件 | 做什么的 | 大概多少钱 |
|---|---|---|
| **STM32F103C8T6** 最小系统板 | 主控芯片，负责"思考"：读传感器、拼报文、控制 WiFi 模块 | 10~20 元 |
| **ESP8266-01S** | WiFi 模块，负责"联网"：连热点、建 TCP 连接、收发数据 | 8~15 元 |
| **DHT11** 温湿度传感器 | 感知环境：测温度和湿度 | 3~8 元 |
| 面包板 + 杜邦线若干 | 把上面的零件连起来 | 10 元左右 |
| USB-TTL 串口模块（如 CH340） | 烧录程序 + 看串口打印的调试信息 | 5~10 元 |
| 手机充电器 / 5V 电源 | 给整个系统供电 | 随便一个 |

> 💡 总成本大约 **50 元以内**，比一杯奶茶贵不了多少。

## 1.3 接线关系

```
                  ┌─────────────────────┐
                  │   STM32F103C8T6      │
                  │                      │
  DHT11 ── PB12 ─┤  GPIO 读取温湿度      │
                  │                      │
  ESP8266 ── PA2 ─┤  USART2_TX → ESP RX  │
  ESP8266 ── PA3 ─┤  USART2_RX ← ESP TX  │
  ESP8266 ── PB1 ─┤  RST (复位控制)      │
                  │                      │
  USB-TTL ── PA9 ─┤  USART1_TX (打印日志) │
  USB-TTL ── PA10 ┤  USART1_RX (暂时不用) │
                  └─────────────────────┘
```

> **新手最常翻车的地方**：TX 和 RX 要**交叉**接 —— STM32 的 TX 接 ESP8266 的 RX，
> STM32 的 RX 接 ESP8266 的 TX。同编号对着接是不行的。

## 1.4 软件分几层

整个固件（跑在 STM32 里的程序）是**分层**设计的，像大楼一样：

```
┌──────────────────────────────────────────────────────┐
│  APP 层 (应用)                                        │
│  app_main.c  app_config.h  task_wifi.c  task_dht11.c │ ← 你大部分时间改这里
│  任务创建、WiFi 联网、上报策略、JSON 拼装               │
├──────────────────────────────────────────────────────┤
│  协议层 (通信协议)                                     │
│  mqtt.c  mqtt.h                                       │ ← 只跟 MQTT 协议有关
│  MQTT 报文拼装：CONNECT / PUBLISH / PINGREQ            │
├──────────────────────────────────────────────────────┤
│  BSP 层 (板级驱动)                                     │
│  DHT11/  ESP8266/  bsp_delay.c  bsp_delay.h           │ ← 跟硬件一一对应
│  每个外设的底层驱动                                     │
├──────────────────────────────────────────────────────┤
│  FreeRTOS (实时操作系统内核)                            │
│  任务调度、队列通信、内存管理                             │ ← 帮上面三层"同时做多件事"
├──────────────────────────────────────────────────────┤
│  HAL 库 (STM32 官方硬件抽象层)                          │
│  CubeMX 自动生成的初始化代码                             │ ← ST 官方提供
└──────────────────────────────────────────────────────┘
```

**分层的意义**：每一层只关心自己的事，不越界。

- APP 层写"多久发一次数据"，不需要知道 MQTT 报文长什么样
- 协议层拼 MQTT 报文，不需要知道底层是 WiFi 还是有线网
- BSP 层管硬件时序，不需要知道上层在跑什么 RTOS

所以换传感器 / 换云平台 / 换通信模块，都只动对应的一层，
其他层**一个字都不用改**。

## 1.5 数据流全景

数据是一步一步往上"流"的：

```
DHT11 传感器                         OneNET 云平台
    │                                    ▲
    │ ① 每 2 秒读一次                     │
    ▼                                    │
[DHT11 驱动]                             │
    │                                    │
    │ ② 通过队列投递                      │  ⑧ 控制台显示数据点
    ▼                                    │
[队列 g_xDht11Queue]                    │
    │                                    │
    │ ③ WiFi 任务从队列取出               │
    ▼                                    │
[WiFi 任务]                              │
    │                                    │
    │ ④ 拼成 JSON 报文                   │
    │ ⑤ 交给 MQTT 层打包成 MQTT 报文      │
    ▼                                    │
[MQTT 层 mqtt.c]                        │
    │                                    │
    │ ⑥ 通过 ESP8266_TCPSend 发送        │
    ▼                                    │
[ESP8266 驱动]                           │
    │                                    │
    │ ⑦ AT+CIPSEND → TCP → 互联网       │
    ▼                                    │
ESP8266 WiFi 模块 ──── 路由器/热点 ──── 互联网 ──── OneNET 平台
```

关键点：
- **第 ② 步用了队列**（FreeRTOS 的 `xQueue`），所以 DHT11 采集和 WiFi 上报
  是两个**独立的任务**，采集不会因为网络卡住而停下来。
- **第 ④ 步拼 JSON 在第 ⑤ 步之前**：业务格式和协议格式分开。
- **第 ⑦ 步对 ESP8266 来说只是"把数据塞进 TCP 连接"**，它不知道上面跑的是 MQTT。

## 1.8 第一步做什么

如果你是零基础刚拿到这块板子：

1. **先读本总纲**（你就在这）—— 理解全局
2. **然后读笔记② FreeRTOS 任务框架** —— 理解"两个任务"怎么同时跑的
3. **接着读笔记③ ESP8266 / 笔记④ MQTT / 笔记⑤ DHT11** —— 理解每一层在干什么
4. **最后读笔记⑥ 调试方法 + 笔记⑦ 总结回顾** —— 学会怎么验证每一步对不对

> ⚠️ 不要跳过第二步直接去改代码。这个项目最难的部分不是写代码，
> 而是代码烧进去了、串口有输出了、但数据没上去 —— 你**不知道问题在哪一层**。
> 分层排查的能力比写代码本身重要得多。
