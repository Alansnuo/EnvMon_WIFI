# ESP8266 知识点与 AT 指令手册

> 这份笔记是**查阅用的参考手册**：硬件常识、固件知识、AT 指令速查。
> 代码如何实现的见《ESP8266_代码思路笔记.md》。

---

## 第一部分：硬件知识

### 1.1 供电 —— 新手最容易翻车的地方

| 项目 | 要求 |
|---|---|
| 工作电压 | **3.3V**（不是 5V！） |
| 峰值电流 | **可达 300mA**（WiFi 发射瞬间） |
| 平均电流 | 约 70~80mA |

**两个致命误区：**

**误区一：接到 5V 上。** 会直接烧毁模块。ESP8266 是 3.3V 器件。

**误区二：用 STM32 板上的 3.3V 稳压器直接供电。**
很多开发板的 AMS1117-3.3 输出能力只有 100~200mA，而 ESP8266 发射瞬间要 300mA。
结果是**能连上 WiFi，但一发数据就重启** —— 因为电压被拉垮触发欠压复位。

**正确做法**：独立 3.3V 电源（≥500mA），并在模块 VCC-GND 之间并一个
**100~470µF 的电解电容**做储能，吸收发射瞬间的电流尖峰。

> 现象识别：如果你的模块偶尔重启、AT 命令时好时坏，**先怀疑供电**，再怀疑代码。

### 1.2 电平匹配

ESP8266 的 IO **不是 5V 耐受**的：

| 方向 | 是否需要处理 |
|---|---|
| STM32 TX (3.3V) → ESP8266 RX | 不用，电压匹配 |
| ESP8266 TX (3.3V) → STM32 RX | 不用，多数 STM32 引脚 3.3V 下判高有效 |
| 5V 单片机 TX → ESP8266 RX | **必须分压或电平转换** |

STM32F103 是 3.3V 器件，所以**直接对接即可**，不需要电平转换模块。
如果网上买的是带电平转换的转接板，也直接用没问题。

### 1.3 ESP-01 / ESP-01S 引脚

```
         ┌─────────────┐
   GND ──┤1          8├── VCC (3.3V)
 GPIO2 ──┤2          7├── CH_PD (EN)
 GPIO0 ──┤3          6├── RST
   RX  ──┤4          5├── TX
         └─────────────┘
         (元件面朝上，天线朝外)
```

| 引脚 | 作用 | 本项目接线 |
|---|---|---|
| VCC / GND | 3.3V 供电 | 独立 3.3V |
| TX | 模块发送 → 接单片机 RX | PA3 (USART2_RX) |
| RX | 模块接收 ← 接单片机 TX | PA2 (USART2_TX) |
| **CH_PD (EN)** | **使能脚，必须拉高** | 接 3.3V（**不拉高模块完全不工作**） |
| RST | 复位，低电平复位 | **PB1** |
| GPIO0 | 启动模式选择 | 悬空/拉高 = 运行模式；**上电时拉低 = 烧录模式** |
| GPIO2 | 必须为高 | 悬空即可 |

**最常见的接线错误**：忘了接 **CH_PD**。这个脚不拉高，模块连 AT 都不回。

### 1.4 串口参数

| 参数 | 值 |
|---|---|
| 波特率 | **115200**（新固件默认） |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验 | 无 |
| 流控 | 无 |

> **注意**：部分老固件的默认波特率是 **9600**。如果发 AT 没反应但接线正确，
> 试试改成 9600。

## 第二部分：固件知识

### 2.1 AT 固件 ≠ 其他固件

ESP8266 可以烧多种固件，**引脚和接线一样，但用法完全不同**：

| 固件类型 | 特点 | 能否用本驱动 |
|---|---|---|
| **AT 固件** | 官方出厂固件，用文本命令控制 | ✅ 本驱动就是为它写的 |
| NodeMCU | Lua 脚本，交互式 | ❌ |
| MicroPython | Python | ❌ |
| Arduino core | 直接用 Arduino 代码 | ❌ |

**买模块时务必确认是"AT 固件"版**。很多模块默认烧的是 NodeMCU 固件，
发 AT 没有任何反应 —— 这不是坏了，是固件不对。

### 2.2 固件版本差异：v1.x vs v2.x

用 `AT+GMR` 查版本。两个大版本有**行为差异**：

| 差异点 | v1.x | v2.x |
|---|---|---|
| `AT+CIFSR` 返回 | `+CIFSR:STAIP,"192.168.1.100"` | 直接返回 `192.168.1.100` |
| 无后缀命令 | `AT+CWMODE` 可用 | **被移除**，必须用 `_CUR` 或 `_DEF` |
| `AT+CIPSTART` 参数 | 顺序不同 | 有变化 |

这就是 `ESP8266_GetIPAddress()` 里为什么要写**两套解析逻辑**的原因：

```c
p = strstr((char *)ESP8266_RxBuf, "STAIP,\"");   // v1.x 格式
if (p != NULL) { p += 7; }                        // 跳过前缀
else {
    // v2.x：直接定位第一个数字
    p = (char *)ESP8266_RxBuf;
    while (*p != '\0' && (*p < '0' || *p > '9')) p++;
}
```

写驱动时**要假设固件版本未知**，解析尽量宽松。

### 2.3 回显（Echo）

**出厂默认回显是开着的**，你发什么模块就原样回什么：

```
发送: AT
接收: AT        ← 这是回显
      OK        ← 这才是真正的响应
```

**必须关掉**（`ATE0`），原因有两个：

1. 回显内容会混进接收缓冲区。如果发的命令里恰好包含 "OK" 之类的关键字，
   `strstr` 会**误判成功**。
2. 白白占用缓冲区空间。

关掉后：

```
发送: AT
接收: OK        ← 干净了
```

## 第三部分：AT 指令规范

### 3.1 命令格式

```
AT+<命令>=<参数1>,<参数2>,...\r\n
```

- 必须以 **`\r\n`**（回车换行）结尾，缺一不可
- 字符串参数要加**双引号**
- 逗号分隔多个参数，**不能有空格**
- 大小写敏感（一般全大写）

**正确 vs 错误示例：**

| 写法 | 结果 |
|---|---|
| `AT+CWJAP="MyWiFi","12345678"\r\n` | ✅ |
| `AT+CWJAP = "MyWiFi","12345678"\r\n` | ❌ 等号旁有空格 |
| `AT+CWJAP="MyWiFi","12345678"` | ❌ 缺 `\r\n` |
| `AT+CWJAP=MyWiFi,12345678\r\n` | ❌ 缺引号 |

### 3.2 响应类型

**有两种响应，性质完全不同：**

**① 同步响应** —— 对你发的那条命令的直接回复，**每次必有一条**：

| 响应 | 含义 |
|---|---|
| `OK` | 命令执行成功 |
| `ERROR` | 命令语法错误 / 参数非法 |
| `FAIL` | 命令语法对，但操作失败（如连接被拒） |
| `no change` | 设置的值和当前值相同（**注意：这不是错误**） |
| `busy p...` | 上一条命令还没执行完 |
| `SEND OK` | 数据发送成功 |
| `>` | 提示可以发送裸数据了 |

**② 主动上报（Unsolicited）** —— 模块自己冒出来的，**不请自来**：

| 上报 | 含义 |
|---|---|
| `ready` | 模块启动完成 |
| `WIFI CONNECTED` | 连上路由器 |
| `WIFI GOT IP` | 拿到 IP（DHCP 完成） |
| `WIFI DISCONNECT` | 掉线了 |
| `+IPD,<长度>:<数据>` | **收到了 TCP 数据** |

> ✅ `+IPD` 是 TCP 通信的核心，**本项目驱动已经处理它了** ——
> `ESP8266_TCPRecvRaw()`（`esp8266.c:605`）里有完整的剥离状态机，
> 连"头被切成两半、跨两次收上来"都处理了；MQTT 层的 CONNACK / PINGRESP
> 全靠它。逐行原理见
> [详解/02-ESP8266接收架构与+IPD剥离](../../详解/09-ESP8266接收架构与+IPD剥离.md)。
> （这条以前写的是"没有处理" —— 那是更早那版驱动的说法。）

### 3.3 `_CUR` 和 `_DEF` 后缀（v2.x）

很多配置类命令有两个变体：

| 后缀 | 含义 | 是否写入 Flash |
|---|---|---|
| `_CUR` | 只对**本次运行**生效 | 否 |
| `_DEF` | 写入 Flash，**下次上电仍生效** | 是 |
| 无后缀 | v1.x 的写法，等同于 `_CUR` | — |

**选择建议**：

- WiFi 密码这类**基本不变**的配置 → 用 `_DEF`，省去每次配置
- 调试时频繁改的 → 用 `_CUR`，避免反复擦写 Flash（Flash 有寿命）

## 第四部分：本项目用到的指令详解

| 指令 | 作用 | 期待响应 | 代码位置 |
|---|---|---|---|
| `AT` | 测试连通性 | `OK` | `ESP8266_Test()` |
| `AT+RESTORE` | 恢复出厂（可选，开关控制，默认关） | `ready` | `ESP8266_Init()` |
| `ATE0` | 关闭回显 | `OK` | `ESP8266_Init()` |
| `AT+CWAUTOCONN=0` | 关掉模块自己的自动重连 | `OK` | `ESP8266_Init()` |
| `AT+CWMODE=<n>` | 设置 WiFi 模式 | `OK` 或 `no change` | `ESP8266_SetWiFiMode()` |
| `AT+CWQAP` | 断开当前关联（连之前先清干净） | `OK` | `ESP8266_ConnectWiFi()` |
| `AT+CWJAP="ssid","pwd"` | 连接路由器 | `OK` | `ESP8266_ConnectWiFi()` |
| `AT+CWLAP` | 扫描周边热点（只在失败分支跑一次） | `OK` | `ESP8266_ScanAP()` |
| `AT+CIFSR` | 查询本机 IP | `OK` | `ESP8266_GetIPAddress()` |
| `AT+CIPMUX=0` | 设为单连接模式 | `OK` | `ESP8266_TCPConnect()` |
| `AT+CIPSTART` | 建立 TCP 连接 | `CONNECT` | `ESP8266_TCPConnect()` |
| `AT+CIPSEND=<n>` | 声明要发 n 字节 | `>` | `ESP8266_TCPSend()` |
| `AT+CIPCLOSE` | 断开 TCP | `OK` | `ESP8266_TCPDisconnect()` |
| `AT+CIPSTATUS` | 查询连接状态 | `OK` | `ESP8266_GetStatus()` |

> 客户端的**接收**（服务器发来的数据）不在这张表里 —— 那不用发命令，
> 数据自己会以 `+IPD` 的形式上来，由 `ESP8266_TCPRecvRaw()`
> （`esp8266.c:605`）剥好交出去。

### 4.1 `AT+CWMODE` 模式值

| 值 | 模式 | 含义 |
|---|---|---|
| 1 | STA | 客户端，**连别人的路由器**（本项目用这个） |
| 2 | AP | 热点，自己是路由器 |
| 3 | STA+AP | 两者同时 |

**注意**：如果设置的值和当前值相同，模块返回 **`no change` 而不是 `OK`**。
这不是错误，但如果不处理，代码会误判成失败。所以：

```c
if (ESP8266_SendCmd(cmd, "OK", ESP8266_TIMEOUT) == ESP8266_OK) return ESP8266_OK;
if (strstr((char *)ESP8266_RxBuf, "no change") != NULL)      return ESP8266_OK;
return ESP8266_ERR_AT;
```

### 4.2 `AT+CWJAP` 连接路由器

```
发送: AT+CWJAP="MyWiFi","12345678"
接收: WIFI CONNECTED
      WIFI GOT IP

      OK
```

注意 `OK` 之前有一堆主动上报。这就是为什么用 `strstr` 在整个缓冲区里找
`OK` 是合理的 —— 响应不在一行里，而是散在多行。

**失败情形**（官方定义，`+CWJAP:<code>` 后跟 `FAIL`）：

| 返回 | 原因 |
|---|---|
| `+CWJAP:1` `FAIL` | **连接超时** —— 热点不在范围内、信号太弱，或模块正忙 |
| `+CWJAP:2` `FAIL` | **密码错误** |
| `+CWJAP:3` `FAIL` | **找不到目标 AP** —— SSID 写错、热点关了，或者那是个 5GHz 网络 |
| `+CWJAP:4` `FAIL` | **连接失败：热点主动拒绝了**（重点，见下） |

⚠️ **`+CWJAP:4` 不是"超时"，是"被拒绝"** —— 这个区别很要命。
本项目就栽在它上面：**手机热点把这块板子拉进了黑名单**
（MAC 黑名单 / "已阻止的设备" / 只允许已添加的设备），
于是模块**扫描能扫到、信号还满格，就是连不上**，一路报 4。

黑名单**只拒绝关联、不挡 beacon**，所以"扫得到"和"被拒绝"一点都不矛盾 ——
**看到"信号满格却连不上"，先翻手机热点的黑名单，别怀疑模块。**

按可能性排的原因：

1. 手机把这个板子的 MAC 拉黑了，或者开了"仅允许已添加的设备"
2. 热点客户端数满了
3. 密码值不对 —— 它本该报 `+CWJAP:2`，但"扫得到却连不上"的现场也要把它
   算进嫌疑（`task_wifi.c:88` 那张清单就是这么排的）

**怎么快速分辨**：失败时扫一遍周边热点（`AT+CWLAP`）——
名单里有这个热点 → 热点活着、信号也在，多半就是**被拒绝**；
名单里没有 → 热点关了、走远了，或者根本不是 2.4GHz。
本工程的 `WifiDiagScan()`（`task_wifi.c:97`）干的就是这件事，
注释和排查清单在 `task_wifi.c:84-90`。

> 另外两个容易混淆的点：
> - 驱动在发 `AT+CWJAP` 之前会先发一条 `AT+CWQAP` 断开残留关联
>   （`esp8266.c:385`）。模块卡在"半连不连"时不清干净会一直连不上，
>   症状也长得很像 4。
> - 对照阅读：[详解/03-ESP8266-WiFi模块驱动](../../详解/03-ESP8266-WiFi模块驱动.md)
>   里的错误码表（那份是对的，这份以前写反了）。

### 4.3 `AT+CIPMUX` —— 为什么必须先设 0

| 值 | 模式 | `AT+CIPSTART` 语法 |
|---|---|---|
| 0 | 单连接 | `AT+CIPSTART="TCP","ip",port` |
| 1 | 多连接 | `AT+CIPSTART=<id>,"TCP","ip",port` ← **多一个 id 参数** |

**如果残留在多连接模式**，用单连接的语法去连，会直接报错。
所以 `ESP8266_TCPConnect()` 里每次都先发一次 `AT+CIPMUX=0` 兜底。

### 4.4 `AT+CIPSEND` —— 两步式交互

```
发送: AT+CIPSEND=5          ← 声明要发 5 字节
接收: 
      OK
      >                     ← 提示符：可以发了
发送: HELLO                 ← 裸数据，不是 AT 命令
接收: 
      SEND OK               ← 确认发送成功
```

**关键点**：

- `AT+CIPSEND` 后面跟的**是长度，不是数据**
- 看到 `>` 才能发数据，**顺序不能乱**
- 数据本身**不加引号、不加 `\r\n`**（除非数据内容需要）
- 长度必须**完全准确**，多一个少一个都会导致模块等待或截断

发送完毕后也可收到 `SEND FAIL`，表示模块发送失败（通常是连接已断）。

### 4.5 `AT+CIPSTATUS` 状态码

```
STATUS:<stat>
+CIPSTATUS:<link ID>,<type>,<remote IP>,<remote port>,<local port>,<tetype>

OK
```

| `stat` | 含义 |
|---|---|
| 0 | 未初始化 |
| 1 | 已初始化，未连接 WiFi |
| 2 | 已连 WiFi，拿到 IP，无 TCP 连接 |
| 3 | **已建立 TCP 传输连接** |
| 4 | 连接已断开 |
| 5 | 未连接 AP |

## 第五部分：其他常用 AT 指令速查

> 下面这些**大多本项目没用到**，但做完整项目时很可能会需要。
> 有 4 条例外，用 ⭐ 标出来了 —— `AT+RESTORE`、`AT+CWLAP`、`AT+CWQAP`、
> `AT+CWAUTOCONN` 其实都在用，第四部分的表里也有它们。

### 5.1 基础类

| 指令 | 作用 | 示例响应 |
|---|---|---|
| `AT+RST` | **软复位**（不依赖 RST 引脚） | `ready` |
| `AT+GMR` | 查固件版本 | `AT version:...` `SDK version:...` |
| `AT+RESTORE` ⭐ | **恢复出厂设置**（清掉存的 WiFi 密码）—— 本项目用上了：`ESP8266_FACTORY_RESET_ON_BOOT` 开关控制，默认关 | `ready` |
| `AT+UART_CUR=<波特率>,<数据位>,<停止位>,<校验>,<流控>` | 改本次串口参数 | `OK` |
| `AT+UART_DEF=...` | 改串口参数并保存 | `OK` |
| `AT+SLEEP=<模式>` | 进入休眠省电 | `OK` |
| `AT+CSYSWDTDIS` | 关闭系统看门狗 | `OK` |

**`AT+RST` vs 硬复位（拉 RST 引脚）的区别：**

| | `AT+RST` | 拉低 RST 引脚 |
|---|---|---|
| 依赖串口通 | 是（串口挂了就没用） | 否 |
| 能救活假死模块 | 可能不行 | 通常可以 |
| 需要额外引脚 | 不需要 | 需要 |

本驱动用的是**硬复位**，更可靠。

### 5.2 WiFi 类

| 指令 | 作用 |
|---|---|
| `AT+CWLAP` ⭐ | **扫描周围 WiFi**（调试信号问题时很有用）—— 本项目用上了：`ESP8266_ScanAP()` 在连线失败时跑一次 |
| `AT+CWLAPOPT` | 设置扫描结果的显示格式 |
| `AT+CWQAP` ⭐ | 断开当前路由器连接 —— 本项目用上了：连之前先清干净（见 4.2） |
| `AT+CWSAP_CUR="ssid","pwd",<通道>,<加密>` | 配置自己的热点（AP 模式） |
| `AT+CWLIF` | 查看已连到本机热点的设备 |
| `AT+CWAUTOCONN=<0/1>` ⭐ | 是否上电自动连接上次的 AP —— 本项目用上了：开机就发 `=0` 把它关掉（见 4.2） |
| `AT+CIPSTA_CUR="192.168.1.50"` | **设置静态 IP**（不用 DHCP） |
| `AT+CWDHCP_CUR=<模式>,<0/1>` | 开启/关闭 DHCP |
| `AT+CIPSTAMAC_CUR="aa:bb:cc:dd:ee:ff"` | 设置 MAC 地址 |
| `AT+CWSTARTSMART` | **一键配网 SmartConfig**（手机 App 发密码） |
| `AT+CWSTOPSMART` | 停止 SmartConfig |
| `AT+PING="www.baidu.com"` | **ping 测试**（排查网络问题神器） |
| `AT+CIPDOMAIN="www.baidu.com"` | **域名解析**，返回 IP |

**`AT+CWLAP` 扫描示例：**

```
发送: AT+CWLAP
接收: +CWLAP:(3,"MyWiFi",-45,"aa:bb:cc:dd:ee:ff",1)
      +CWLAP:(4,"CMCC-123",-78,"11:22:33:44:55:66",6)

      OK
```

字段含义：`(加密方式, SSID, 信号强度dBm, MAC, 信道)`

信号强度参考：

| dBm | 质量 |
|---|---|
| -30 ~ -50 | 极好 |
| -50 ~ -70 | 良好 |
| -70 ~ -80 | 一般，可能不稳 |
| < -80 | 很差 |

### 5.3 TCP/IP 类

| 指令 | 作用 |
|---|---|
| `AT+CIPSERVER=<0/1>[,<端口>]` | **建立 TCP 服务器**（做服务端） |
| `AT+CIPSERVERMAXCONN=<n>` | 最大并发连接数 |
| `AT+CIPSTO=<秒>` | 服务器自动断开超时 |
| `AT+CIPSENDEX=<n>` | 类似 CIPSEND，但支持转义发送 `\0` |
| `AT+CIPDINFO=<0/1>` | `+IPD` 里是否附带对方 IP 和端口 |
| `AT+CIPRECVTYPE` | 数据接收模式：0=主动上报，1=被动查询（v2.x） |
| `AT+CIPRECVDATA=<n>` | 被动模式下主动读取 n 字节（v2.x） |
| `AT+CIPRECVLEN` | 查询缓冲区里还有多少字节没读（v2.x） |
| `AT+CIUPDATE` | 在线升级固件 |

> **v2.x 的接收模式值得知道一下**：`AT+CIPRECVTYPE=1` 让数据**不主动上报**，
> 而是等单片机用 `AT+CIPRECVDATA` 来取。这是"别让 `+IPD` 打断命令响应"
> 的**另一种思路**，**本项目没有走这条路** —— 3.2 说的那个问题已经由驱动
> 内部的 `+IPD` 剥离状态机解决了（`esp8266.c:605`），不用再依赖 v2.x 固件
> 的新命令：模块固件版本是不保证的，能不用新命令就不用。

### 5.4 透传模式（Transparent Transmission）

**这是 ESP8266 最有用的功能之一**，值得单独讲。

**问题**：正常模式下，每发一次数据都要走 `AT+CIPSEND` 两步式流程，
开销大、代码复杂，而且 AT 命令和业务数据混在一起。

**透传模式下**：串口发什么，就直接转发到 TCP 连接，**不解析 AT 命令**。
对单片机来说，ESP8266 变成了一个"串口转 WiFi 的透明管道"。

**开启流程：**

```
AT+CIPMODE=1              → OK          开启透传模式
AT+CIPSTART="TCP","ip",port → CONNECT   建立连接
AT+CIPSEND                → >           进入透传（注意：不带长度参数！）
然后就可以：直接发数据 → 直接收到数据（不再有 SEND OK / +IPD 包装）
```

**退出透传**：发送 `+++`（**前后要留至少 1 秒的静默期，且不发 `\r\n`**），
然后发 `AT+CIPMODE=0` 关闭。

**透传 vs 普通模式对比：**

| | 普通模式 | 透传模式 |
|---|---|---|
| 发数据 | `AT+CIPSEND=n` → 等 `>` → 发 | 直接发 |
| 收数据 | `+IPD,n:data` 包装 | 直接收 |
| 单片机负担 | 重（要解析 AT） | 轻 |
| 灵活性 | 高（可随时改配置） | 低（透传期间收不到 AT） |
| 适用场景 | 需要精细控制 | 持续数据传输 |

**注意**：透传期间**无法用 AT 命令查询状态**，也收不到 WiFi 断线通知。
如果连接断了，数据会静默丢失。所以透传适合稳定的持续传输场景。

## 第六部分：常见问题排查

| 现象 | 可能原因 | 排查方法 |
|---|---|---|
| 发 AT 完全无响应 | ① CH_PD 没接高 ② TX/RX 接反 ③ 波特率不对 ④ 供电不足 ⑤ 不是 AT 固件 | 先用 USB-TTL 单独测模块 |
| 能连 WiFi，一发数据就重启 | **供电电流不足** | 换独立 3.3V/500mA 电源，加 100µF 电容 |
| AT 有时回有时不回 | 波特率不对 / 供电不稳 / 串口线太长 | 降低波特率到 9600 试试 |
| 连接 WiFi 总是失败 | 信号弱（`+CWJAP:1`）/ 密码错（`2`）/ 是 5GHz 网络（`3`）/ **热点把设备拉黑了**（`4`） | **ESP8266 只支持 2.4GHz！** 扫得到却连不上，先翻热点黑名单（见 4.2） |
| 命令返回 ERROR | 语法错（缺 `\r\n`、缺引号、有空格） | 对照第三部分 3.1 |
| 返回 `busy p...` | 上一条命令还没执行完 | 加延时，或重试 |
| 收到的数据里混入命令本身 | **回显没关** | 发 `ATE0` |
| 连上了但收不到服务器数据 | 服务器没发 / 主题不对 | 用 `AT+CIPSTATUS` 看状态码；`+IPD` 已经由驱动剥好了（`esp8266.c:605`），不用再怀疑它 |
| 连接过一会儿就断 | 服务器超时断连 / 信号弱 | 加心跳包 |

> **ESP8266 只支持 2.4GHz WiFi** —— 这是最常见的"连不上"原因。
> 很多家用路由器默认双频合一，如果路由器把设备往 5GHz 推，就连不上。
> 解决办法：在路由器设置里把 2.4G 和 5G 的 SSID 分开。

## 第七部分：调试利器

### 7.1 分步排查法

网络问题往往涉及多个环节，**不要一次性跑完整流程**。
按下面的顺序逐步验证，每一步成功了再进行下一步：

```
① AT              → 模块活着吗？串口通吗？
② AT+GMR          → 固件版本对不对？
③ AT+CWMODE=1     → 模式对吗？
④ AT+CWJAP=...    → 能连路由器吗？
⑤ AT+CIFSR        → 拿到 IP 了吗？
⑥ AT+PING="www.baidu.com"  → 能上外网吗？
⑦ AT+CIPSTART=... → 能连服务器吗？
⑧ AT+CIPSEND=...  → 能发数据吗？
```

哪一步断了，问题就出在那一步。

### 7.2 保留原始响应

本驱动的 `APP/task_wifi.c` 里有这么一段（`WifiConnect()` 的失败分支，
`task_wifi.c:155-156`）：

```c
printf("WiFi Connect Failed! ESP8266 response:\r\n");
printf("%s\r\n", (char *)ESP8266_GetRxBuf());
```

**失败时把模块的原始回复打印出来**，而不是只报一个错误码。
这是极其实用的调试习惯 —— 模块会告诉你具体哪里错了（`+CWJAP:2` 就是密码错），
比"连接失败"这四个字有用得多。
（这段不在 `main.c` 里 —— main.c 连一个 ESP8266 的函数都没调用过。）

紧接着还会跑一次热点扫描（`WifiDiagScan()`，`task_wifi.c:97`），
**顺序不能反** —— 扫描会把 `RxBuf` 冲掉，得先把原始应答打完
（`task_wifi.c:157-158` 有注释提醒）。
