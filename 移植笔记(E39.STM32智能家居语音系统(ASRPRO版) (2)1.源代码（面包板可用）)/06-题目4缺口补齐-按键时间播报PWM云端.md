## 二、按键（必做2、必做4 都要）

### 板上有哪些脚能接按键

网表里"只出现 MCU 一侧、没连任何器件"的脚，就是全部的候选：

| 端口 | 空闲脚 |
|---|---|
| PA | PA0、PA1、PA4、PA5、PA6、PA7、**PA8**、PA11、PA12、PA15 |
| PB | **PB0**、PB3、PB4、PB5、PB10、PB11、PB13、PB14、PB15 |

⚠️ **前提：网表只能证明这些脚"没接东西"，证明不了板上留了焊盘。** 先拿万用表或看板子确认有能焊线的位置（过孔/焊盘/排针），再决定用哪几个。这是本篇唯一需要动手确认的地方。

**推荐：PA0 / PA1 / PA4 / PA5**，四个按键。理由：

- 这四个脚**没有任何复用冲突**，配成上拉输入即可，不需要 AFIO 重映射；
- 不占任何定时器通道（PA8 要留给 PWM，见第六节）。

**要避开的三类脚**：

| 脚 | 为什么避开 |
|---|---|
| PB6~PB9 | 已被 BH1750 和 OLED 占满 |
| PB3 / PB4 / PA15 | 是 **JTAG 脚**（JTDO / NJTRST / JTDI）。复位后默认是 JTAG 功能，当 GPIO 用必须先 `__HAL_AFIO_REMAP_SWJ_NOJTAG()` 关掉 JTAG（保留 SWD 下载）。能用，但多一步，没必要 |
| PA11 / PA12 | USB DM/DP，虽然本工程不用 USB，但留着以后有用 |

### 电路（不需要外部元件）

```
按键一脚 → MCU 引脚
按键另一脚 → GND
```

靠 MCU **内部上拉**（`GPIO_PULLUP`），按下读到 `0`，松开读到 `1`。**不用外接电阻，不用电容**。四个键共 4 根线。

⚠️ **不要**学参考工程 `Key.c` 那样把按键接在 PB6~PB9——那四个脚在这块板上已经是 I2C 总线了。

### 参考工程的 `Key.c` 有什么可抄的

`Hardware/Key.c` 里有一套**完整的长按/短按/连按状态机**，思路是对的（每个键四五个计数器：消抖计数、长按计数、连按计数）。但它有两个问题：

1. **它靠"每次调用扫一遍 4 个键"驱动**，调用周期必须稳定。参考工程是在 TIM2 中断里按固定节奏调的（`KEY_DELAY_TIME` / `KEY_LONG_TIME` / `KEY_Continue_TIME` 这几个阈值都是**按调用次数**算的，不是按毫秒）。你换到 FreeRTOS 任务里，**必须让任务的 `vTaskDelay` 周期和这些阈值对应上**，否则长按会变成"要按很久"或者"一碰就长按"。
2. 开头有一行**重复声明**（`key1_lock_flag` 那几个变量写了两遍），是手滑，抄的时候删掉。

### 驱动设计

新建 `BSP/key/key.h`：

```c
#ifndef __KEY_H
#define __KEY_H

#include "main.h"

/* PCB 上没有按键, 这四根线是飞线接到空闲脚上的 —— 见 06 篇第二节 */
#define KEY1_PORT  GPIOA
#define KEY1_PIN   GPIO_PIN_0
#define KEY2_PORT  GPIOA
#define KEY2_PIN   GPIO_PIN_1
#define KEY3_PORT  GPIOA
#define KEY3_PIN   GPIO_PIN_4
#define KEY4_PORT  GPIOA
#define KEY4_PIN   GPIO_PIN_5

/* Key_Scan() 的返回值. 0 = 本次没有事件 */
typedef enum {
    KEY_NONE = 0,
    KEY1_SHORT, KEY2_SHORT, KEY3_SHORT, KEY4_SHORT,   /* 短按: 按下即报 */
    KEY1_LONG,  KEY2_LONG,  KEY3_LONG,  KEY4_LONG     /* 长按: 按住 >= 1s */
} KeyEvent;

void      Key_Init(void);
KeyEvent  Key_Scan(void);      /* 每 10ms 调一次, 返回一个事件 */

#endif
```

新建 `BSP/key/key.c`：

```c
/* ============================================================================
 * 按键驱动: 4 个独立按键, 内部上拉, 按下=0
 * Key_Scan() 必须在固定周期(10ms)的上下文里调, 消抖和长按都按调用次数算
 * 短按在"松手"时报, 长按在"按住满 100 次(1s)"时报一次
 * ========================================================================== */

#include "key.h"

#define KEY_DEBOUNCE_CNT   3U     /* 连续 3 次(30ms)读到同电平才算数 */
#define KEY_LONG_CNT       100U   /* 连续 100 次(1s)算长按 */

typedef struct {
    GPIO_TypeDef *port;
    uint16_t      pin;
    uint8_t       stable;     /* 消抖后的电平: 1=松开 0=按下 */
    uint8_t       cnt;        /* 电平变化的累计次数 */
    uint16_t      hold;       /* 已按住的次数 */
    uint8_t       longSent;   /* 长按是否已经报过, 防止按住不放重复报 */
} KeyObj;

static KeyObj s_keys[4] = {
    { KEY1_PORT, KEY1_PIN, 1U, 0U, 0U, 0U },
    { KEY2_PORT, KEY2_PIN, 1U, 0U, 0U, 0U },
    { KEY3_PORT, KEY3_PIN, 1U, 0U, 0U, 0U },
    { KEY4_PORT, KEY4_PIN, 1U, 0U, 0U, 0U },
};

void Key_Init(void)
{
    GPIO_InitTypeDef gpio = {0};

    __HAL_RCC_GPIOA_CLK_ENABLE();

    gpio.Pin   = KEY1_PIN | KEY2_PIN | KEY3_PIN | KEY4_PIN;
    gpio.Mode  = GPIO_MODE_INPUT;
    gpio.Pull  = GPIO_PULLUP;          /* 内部上拉, 不用外接电阻 */
    gpio.Speed = GPIO_SPEED_FREQ_LOW;
    HAL_GPIO_Init(KEY1_PORT, &gpio);
}

KeyEvent Key_Scan(void)
{
    uint8_t i, now;

    for (i = 0U; i < 4U; i++)
    {
        now = (HAL_GPIO_ReadPin(s_keys[i].port, s_keys[i].pin) == GPIO_PIN_SET) ? 1U : 0U;

        if (now != s_keys[i].stable)          /* 电平还没稳, 累计后重新判断 */
        {
            if (++s_keys[i].cnt >= KEY_DEBOUNCE_CNT)
            {
                s_keys[i].cnt    = 0U;
                s_keys[i].stable = now;
                s_keys[i].hold   = 0U;
                s_keys[i].longSent = 0U;

                if (now == 0U) { return (KeyEvent)(KEY1_SHORT + i * 2U); }  /* 按下 */
                /* 松手不报事件: 短按在按下时就报了, 长按在下面报 */
            }
            continue;
        }

        s_keys[i].cnt = 0U;

        if (s_keys[i].stable == 0U)           /* 按住中, 累计时长 */
        {
            if (s_keys[i].hold < 0xFFFFU) { s_keys[i].hold++; }
            if (!s_keys[i].longSent && s_keys[i].hold >= KEY_LONG_CNT)
            {
                s_keys[i].longSent = 1U;
                return (KeyEvent)(KEY1_LONG + i * 2U);
            }
        }
    }

    return KEY_NONE;
}
```

⚠️ **短按在"按下瞬间"就报**（不是等松手）。这样做的好处是响应快、不用额外的"松手标志"。代价是按错了没法反悔——对题目4 的"翻页/加减"够用，因为这些操作本来就是即时生效的。

⚠️ **`Key_Scan()` 必须每 10 ms 调一次**。上面两个阈值是按调用次数算的：`KEY_DEBOUNCE_CNT = 3` 就是 30 ms 消抖，`KEY_LONG_CNT = 100` 就是 1 s 长按。**改了调用周期，这两个数就要跟着改**。

### 怎么接进 FreeRTOS

```c
/* APP/task_key.c */
void TaskKey(void *argument)
{
    KeyEvent ev;

    Key_Init();

    for (;;)
    {
        ev = Key_Scan();
        if (ev != KEY_NONE)
        {
            /* 翻页 / 加减阈值 / 切模式 都从这里分派 */
        }
        vTaskDelay(pdMS_TO_TICKS(10));    /* ← 这个周期不能改, 见上 */
    }
}
```

**优先级别给太高**。10 ms 一次、只读几个 GPIO，给它 **2**（和采集同档）就行；给 1 也行（最坏多等 10 ms，手指感觉不到）。**不要给 3**——WiFi 是 3，按键不该和联网抢。

⚠️ **不要在中断里扫按键**。参考工程放在 TIM2 中断里是裸机的做法；上了 FreeRTOS，10 ms 的任务轮询更简单，也完全不占 CPU（`vTaskDelay` 期间任务根本不运行）。

## 三、当前时间（必做2）

### 先认清一件事：**参考工程没有 RTC**

我 grep 过整个参考工程，`User/`、`Hardware/`、`System/` 里**没有任何 `RTC_Init` / `RTC_SetCounter` 之类的代码**。所以你之前那条"把参考工程的东西搬过来"的路子在时间上是**空的**——时间要从零想。

### 三条路

| 方案 | 要加硬件吗 | 断电后 | 精度 |
|---|---|---|---|
| **A. 上电软件计时** | 不加 | 清零 | 靠 MCU 晶振，很准 |
| **B. ESP8266 网络对时**（推荐） | 不加 | 重新对时即可 | 准（NTP 源） |
| **C. 外挂 RTC 芯片** | 要加 | 有纽扣电池就不丢 | 看芯片 |

### 方案 A：上电计时（最省事，但显示的不是"当前时间"）

一个每秒自增的秒计数器，显示成 `00:12:34` 这种。题目说"当前时间"，严格讲这不算——但如果只是要"屏上有个时间在走"，它最省事。

```c
/* 放在时基任务或任何 1s 周期的任务里 */
static uint32_t s_sec;
void Time_Tick1s(void) { s_sec++; }
```

⚠️ 靠 `vTaskDelay(1000)` 走秒**会有累积误差**（每次至少多一个 tick）。要准就用 `xTaskGetTickCount()` 算：`s_sec = xTaskGetTickCount() / configTICK_RATE_HZ`。**推荐后者，一行，且不漂**。

### 方案 B：ESP8266 网络对时（推荐）

ESP-AT 固件**自带 SNTP**，两条指令：

```
AT+CIPSNTPCFG=1,8,"ntp.aliyun.com"        ← 1=开启, 8=东八区
AT+CIPSNTPTIME?                            ← 查询
```

返回：

```
+CIPSNTPTIME:Fri Oct  3 20:12:34 2025
OK
```

字段顺序是 **星期 月 日 时:分:秒 年**，MCU 从字符串里抠出时/分/秒就行。

**为什么推荐它**：不加任何硬件，复用已经在跑的 USART2，而且对完之后 MCU 自己用 tick 走秒（同方案 A 的 `xTaskGetTickCount()`），断网也不影响显示。

**要做的事**：

1. 在 `BSP/ESP8266/esp8266.c` 里新增两个函数，照 `ESP8266_MQTT_ConnectBroker()` 的写法：

```c
ESP8266_Status ESP8266_SntpEnable(void);
ESP8266_Status ESP8266_SntpGet(char timeStr[], uint16_t len);
```

2. ⚠️ **只能在 WiFi 连上之后调**（`ESP8266_ConnectAP()` 返回 OK 之后）。没联网时 SNTP 起不来。

3. ⚠️ **只有 `TaskWifi` 能碰 ESP8266**（05 篇的硬规矩）。所以对时也要在 `TaskWifi` 里做——连上网之后对一次时，把结果存到全局变量里给 OLED 任务读。

4. ⚠️ **掉电重来要重新对**。别指望它自己保持——模块断电后 SNTP 结果也没了。

⚠️ **`AT+CIPSNTPTIME?` 的返回格式各版本固件可能不同**（有的带秒、有的不带）。**先用串口助手手动发一遍看真实返回**，再写解析。这是本节最容易踩的坑。

### 方案 C：外挂 RTC 芯片

如果非要断电不丢时间：

- **DS1302**（3 线：CE / IO / SCLK）——占 3 个空闲脚，要自己写驱动，参考工程里也没有；
- **DS3231 / PCF8563**（I2C）——**可以和 BH1750、OLED 挂在同一条软件 I2C 总线上**。因为 I2C 是开漏多从机，只要地址不撞（BH1750 是 0x23、SSD1306 是 0x3C），一条总线挂三个器件完全正常。⚠️ 但注意：**BH1750 走 PB6/PB7，OLED 走 PB8/PB9，本来就是两条不同的总线**，要挂第三片得先决定挂哪条，然后把那条总线的 SCL/SDA 也飞线到 RTC 模块上。

### ⚠️ 为什么不能用 STM32 自带的 RTC

STM32F1 的 RTC 要用 **LSE 32.768 kHz 晶振**，接在 **PC14 / PC15** 上——而这两个脚在你的板子上被 **D2 / D3 两个 LED 占了**（见 00 篇决策 3）。

要用自带 RTC，就得二选一：

- **LED 让位**：割掉 PC14/PC15 到 LED 的线，焊上 32.768 kHz 晶振 + 两个匹配电容，LED 改飞线到别的脚；
- **放弃自带 RTC**：走方案 A 或 B。

题目4 里 LED 是要用的（"光线暗则亮灯"的指示），所以**不建议为了 RTC 牺牲 LED**。

## 四、语音播报：让模块开口说话（必做3）

### 04 篇只写了一半

[04-天问语音模块移植.md](04-天问语音模块移植.md) 整篇讲的是**收**：模块识别出人说的话，MCU 解析 6 字节帧。但题目4 要的"播报当前温度25度"是**反方向**——**MCU 主动往模块发**。

我又 grep 了一遍参考工程的 `System/Usart3.c` 和相关文件：**参考工程里没有任何向 USART3 发送数据的代码**（没有 `USART_SendData(USART3, ...)`）。所以这一段**没有任何现成代码可以抄**，只能自己设计。

方向对比：

```
收（04 篇已写）:  人说话 → 天问模块识别 → 串口发 6 字节 → MCU 解析
发（本篇要补）:   MCU 判断要播报 → 串口发字符串 → 天问模块播报 → 喇叭响
```

### ⚠️ 最关键的前置条件：模块固件必须先配好

**MCU 发出去的东西，模块得"认识"才会播。** 天问模块的行为是由它自己那份固件决定的，而那份固件是在**天问自己的图形化 IDE（天问 Block）**里配的——**MCU 侧改不了它**。

所以顺序是：

1. **先在天问 Block 里做两件事**：① 加上"串口接收"的积木块；② 配好"收到什么 → 播报什么"的对应关系；
2. **刷进模块**；
3. **拿串口助手手动发一遍**，确认模块真的开口了；
4. **最后才写 MCU 代码**。

⚠️ **跳过第 3 步直接写 MCU 代码，是最常见的坑**。MCU 发出去石沉大海，你会花半天怀疑串口线，其实是模块固件里根本没配。

### 播报方式：取决于模块固件支持到哪一步

| 方式 | MCU 发什么 | 限制 |
|---|---|---|
| **① 预置条目 + 触发**（最稳） | 一个短码，比如 `"A"` | 只能播**录好的固定句子**，念不了任意数字 |
| **② 数字拼接** | 比如 `"T25"` | 模块端要有"把数字读出来"的积木块，能不能拼成"温度25度"要看固件 |
| **③ TTS 文本合成** | 一整个中文句子 | **要确认模块支不支持**（部分 ASRPRO 固件有 TTS 积木块） |

**先在天问 Block 里翻一遍积木块**，看"播报"那一类里有没有能读变量的。没有就退到方式 ①。

**方式 ① 的实用写法**：把温度分段，比如

| 条件 | MCU 发 | 模块播 |
|---|---|---|
| temp < 15 | `"T1"` | "当前温度偏低" |
| 15 ≤ temp < 30 | `"T2"` | "当前温度舒适" |
| temp ≥ 30 | `"T3"` | "当前温度偏高" |

三档就能覆盖"播报当前温度"的语义，而且**不依赖任何 TTS 能力**，最保险。

### ⚠️ 波特率：一个绕不开的硬约束

参考工程的 `System/Usart3.c` 里写的是

```c
USART_InitStructure.USART_BaudRate = 9600;      /* 天问模块在参考工程里跑 9600 */
```

**你的板子上天问模块接在 USART1，而 USART1 现在是 printf 口，跑的是 115200。两边必须一致**，否则收发全是乱码——04 篇第 5 步的"打出来是乱的"说的就是这个。

关键在于：**波特率是模块固件里配的，不是 MCU 说了算**。所以要么：

- **把模块固件改成 115200**（在天问 Block 里设），USART1 保持 115200 不动——**推荐**，这样 printf 不受影响；
- **把 USART1 改成 9600**，代价是 **printf 也跟着变成 9600**——日志会变慢，而且 CubeMX 里改 USART1 会连带重新生成 `MX_USART1_UART_Init()`。

⚠️ **推荐第一条理由**：改模块固件只动模块，改 MCU 波特率会牵动整个工程（还影响以后所有调试日志的速度）。而且**这一步必须在写播报代码之前做完**——波特率不对的话，你在 MCU 侧怎么改代码都发不出能听懂的东西。

### MCU 侧代码

新建 `BSP/asr/asr.c` 里**再加一个发送函数**（和 04 篇的 `Asr_RxByteFromISR()` 放在同一个文件）：

```c
/* 向天问模块发一串字节, 让它播报.
 * 内容格式由模块固件决定, 见 06 篇第四节 —— MCU 只负责发出去 */
void Asr_Say(const char msg[])
{
    HAL_UART_Transmit(&ASR_UART, (uint8_t *)msg, (uint16_t)strlen(msg), 100);
}
```

⚠️ **`HAL_UART_Transmit` 是阻塞式的**（内部忙等 TC 标志）。一串四五个字节在 115200 下只要 0.4 ms，可以接受。**但绝不要在中断里调它**。

⚠️ **和 printf 抢 USART1 不会互相破坏**。两者都是 MCU 往 PA9 发，同一个 USART 的发送是串行的，不会交错成乱码。只是调的时候，**串口助手上会看到 printf 的日志和播报指令混在一起**——这是预期的，不是 bug。

⚠️ **反过来要小心**：播报指令是**给模块听的**，printf 日志是**给人看的**。模块收到 printf 那堆 ASCII 不会开口（它的解析规则不认），**所以 printf 不会误触发播报**——和 04 篇"printf 不会伪造成识别帧"是同一个道理，只是方向相反。

⚠️ **别在 `TaskWifi` 里调 `Asr_Say()`**。虽然串口能容忍，但会让 WiFi 任务的阻塞时间不可控。播报归语言任务（或专门一个播报任务）。

### 定时播报 vs 按键触发

题目4 说"定时或按按键触发"，两者都是**应用逻辑**，驱动侧只要保证 `Asr_Say()` 能被任何任务安全调用（它内部不碰 FreeRTOS，是线程安全的——只要别两个任务同时发，会串行阻塞，但不会出错）。

## 五、DHT11 的坑：PB12 上挂的是 TDS

这一条是核对网表时发现的，**必须先处理，否则题目4 的必做1 根本跑不起来**。

网表：

```
PB12 ; U1.1 U3.2        ← U3 是 "TDS模块"
```

而 `EnvMon_WIFI` 里：

```c
#define DHT11_PORT      GPIOB
#define DHT11_PIN       GPIO_PIN_12
```

**同一根线不可能既是 TDS 的数据脚又是 DHT11 的数据脚。** 而且再仔细看一遍 `$PACKAGES` 段——**板子上根本没有 DHT11 这个器件**，只有 TDS（U3）。也就是说：**DHT11 是要你自己接的，而它唯一顺理成章的位置（PB12）已经被 TDS 占了。**

### 怎么办

题目4 要 DHT11、**不要 TDS**，所以：

1. **U3 不焊**。如果板子已经焊了，把 U3 拆掉或者至少别插模块；
2. DHT11 的数据线接到 **U3 的 2 号脚焊盘**（那就是 PB12 的网络），或者直接接到 MCU 的 PB12 引脚；
3. DHT11 的 VCC 接 3V3、GND 接 GND；
4. ⚠️ **数据线要一个 4.7k~10k 上拉电阻到 3V3**——DHT11 是单总线，空闲态靠上拉维持高电平。大多数 DHT11 模块自带，裸传感器要自己加。

改完 `DHT11_PIN` **不用动**，还是 `GPIO_PIN_12`。`BSP/dht11/dht11.c` 一个字不用改。

⚠️ 顺便：`MX_GPIO_Init()` 里把 PB12 配成了开漏输出，DHT11 驱动自己会重配成输入/输出切换——**这是现在就能跑的，不用动**。

## 六、PWM 光控（选做2）：更正 03 篇的说法

### 先更正一处

[03-LED指示灯与蜂鸣器移植.md](03-LED指示灯与蜂鸣器移植.md) 里写的是：

> 所以 PWM 调光这条路**在硬件上就是断的**，不是软件能不能实现的问题。

**这句话只对了一半。** 准确的说法是：

> **硬件 PWM 这条路断了**（PC14/PC15 确实没有任何定时器通道），**但软件 PWM 和飞线两条路都还在。**

下面把两条路说清楚。

### 为什么硬件 PWM 确实断了

每个定时器通道只能出在固定引脚上。F103C8 上能用的组合（对照网表看哪些脚被占了）：

| 定时器 | 通道 → 引脚 | 可用吗 |
|---|---|---|
| TIM1 | CH1→**PA8**、CH2→PA9、CH3→PA10、CH4→PA11 | **PA8 可用**（空闲）；PA9/PA10 被天问占 |
| TIM2 | CH1→PA0、CH2→PA1、CH3→PA2、CH4→PA3 | PA0/PA1 可用（但建议留给按键）；PA2/PA3 被 ESP8266 占 |
| TIM3 | CH1→PA6、CH2→PA7、CH3→**PB0**、CH4→PB1 | **PB0 可用**（空闲）；PB1 被 ESP8266 复位占 |
| TIM4 | CH1~CH4 → PB6~PB9 | ⚠️ **TIM4 被 HAL 时基占了**，而且 PB6~PB9 也全被 BH1750/OLED 占了 |

⚠️ **`Core/Src/stm32f1xx_hal_timebase_tim.c` 把 TIM4 配成了 HAL 的 1 ms 时基**（CubeMX 里 "Timebase Source = TIM4"）。所以 **TIM4 绝对不能拿来当 PWM**，动了它整个 `HAL_Delay` / `HAL_GetTick` 全废。PWM 只能用 **TIM1 / TIM2 / TIM3**。

而 **PC14 / PC15 在任何一行里都不出现**——没有定时器能输出到这两个脚。所以硬件 PWM 在 PC14/PC15 上确实做不到。

### 出路 A（推荐）：软件 PWM，零改板

PC14/PC15 是普通 GPIO，**但普通 GPIO 可以靠定时中断自己翻转**——这就是软件 PWM。

原理很简单：开一个 100 μs 周期的定时中断，中断里数一个 0~31 的计数器，**计数器小于占空比档位就点亮、否则熄灭**。32 档 × 100 μs = 3.2 ms 一个完整周期，也就是 **约 310 Hz**——远高于人眼闪烁感知的下限（约 80 Hz），看着是平稳的亮度。

```c
/* BSP/pwm/pwm.c */
#define PWM_STEPS   32U          /* 32 档亮度: 0=全灭 32=全亮 */

static volatile uint8_t s_duty;  /* 0~32, 由 "光线暗则亮灯" 的逻辑写 */
static volatile uint8_t s_cnt;

/* TIM3 的更新中断, 每 100us 一次 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM3)
    {
        s_cnt++;
        if (s_cnt >= PWM_STEPS) { s_cnt = 0U; }

        if (s_cnt < s_duty) { LED1_On(); }
        else                { LED1_Off(); }
    }
}

void PWM_SetDuty(uint8_t duty)
{
    if (duty > PWM_STEPS) { duty = PWM_STEPS; }
    s_duty = duty;
}
```

**代价**：310 Hz × 32 档 = **每秒约 10000 次中断**。在 72 MHz 的 M3 上，每次中断进出加几条指令大约 1~2 μs，**约 1.5% 的 CPU**。可以接受，但要知道它在跑。

⚠️ **这个中断里绝对不能调任何 FreeRTOS API**（不调就没有优先级限制）。中断优先级随便给，建议 5~7。

⚠️ **TIM3 的初始化和 `HAL_TIM_PeriodElapsedCallback` 都要自己写**——`EnvMon_WIFI` 现在没有 TIM3，也没有这个回调函数（`__weak` 的那个在 HAL 里，你写一个同名的强定义就会覆盖它，机制和 `BSP_DelayMs` 一样）。

### 出路 B：飞线到 PA8，用硬件 PWM

如果愿意动电烙铁：

1. 割断 **PC14 到 D2 的线**（或者不焊 D2）；
2. 从 **PA8** 飞一根线到 D2 的阴极（靠 MCU 那一侧的焊盘）；
3. 用 TIM1_CH1 输出硬件 PWM——**零 CPU 开销，任意频率/分辨率**。

代价是改板。**而且注意：PA8 一旦给了 PWM，就不能再当按键用**（见第二节的按键选脚）。

**推荐出路 A**：不改板、代码量小（`PWM_SetDuty()` 一个函数），题目4 要的"模拟调光"效果完全能达到。

### ⚠️ 一个没变的前提

不管走哪条路，**PC14/PC15 的 3 mA 限流限制都还在**（见 00 篇决策 3）。软件 PWM 不会改变这一点——它改变的是"什么时候点亮"，不是"点亮时流多少电流"。**R1/R11 还是要 1 kΩ 以上**。

## 七、云端：EMQX / 阿里云 / 本地服务器（选做1）

### 好消息：换 EMQX 一行驱动代码都不用改

`BSP/ESP8266/esp8266.c` 里用的**全是通用 AT MQTT 指令**，不是 OneNET 专用的：

| 驱动函数 | 发的指令 | 现在填的是 |
|---|---|---|
| `ESP8266_MQTT_SetParam()` | `AT+MQTTUSERCFG=0,1,"<clientId>","<username>","",0,0,""` | OneNET 产品 ID / 设备名 |
| 〃 | `AT+MQTTPASSWORD=0,"<password>"` | OneNET Token |
| 〃 | `AT+MQTTCONNCFG=0,<keepalive>,0,"","",0,0` | 心跳秒数 |
| `ESP8266_MQTT_ConnectBroker()` | `AT+MQTTCONN=0,"<host>",<port>,0` | `mqtts.heclouds.com`, 1883 |
| `ESP8266_MQTT_Publish()` | `AT+MQTTPUB=0,"<topic>","<payload>",0,0` | `$sys/.../post` |

**这些指令对任何 MQTT broker 都是同一个语法。** 换 EMQX 要改的只有两处：

1. **`APP/app_config.h`**：`CFG_MQTT_HOST` 改成你的 EMQX 地址、`CFG_MQTT_CLIENT_ID` 随便填、`CFG_MQTT_USERNAME` / `CFG_MQTT_PASSWORD` 按 EMQX 的认证配置填（EMQX 默认允许匿名，那两个留空就行）；
2. **`APP/app_json.c`**：topic 和 JSON 格式。EMQX 不认 OneNET 的物模型（`{"id":..,"version":..,"params":{...}}`），**换成你自己的 JSON 就行**，比如 `{"temp":25,"humi":60,"lux":320}`——**而且反斜杠转义反而更少**（OneNET 那串 `\\\"` / `\\\,` 是 AT 指令层要求的，只要 payload 里有引号和逗号，转义规则一样不能少，见 05 篇第二节）。

⚠️ **换 broker 之后，Token 那个坑就没有了**。05 篇提到的"Token 过期导致连不上"是 OneNET 特有的，EMQX 自己的账号密码不会过期。

### 阿里云 IoT：不建议

阿里云 IoT 的 MQTT 密码不是固定字符串，而是：

```
password = HMAC-SHA1(clientId + deviceName + productKey + timestamp)
```

**要现算**，而且 `timestamp` 是**会过期**的（阿里云规定不能超过某个时间窗）。ESP8266 的 AT 固件**没有任何加密指令**，算不了 HMAC-SHA1。所以：

- 想在 MCU 侧算 → 要把 SHA1 搬到 STM32 上，还得自己实现 HMAC，代码量不小，而且**时间戳还得准**（回到第三节的问题）；
- 想在 PC 侧算好写死 → 过一段时间就失效，要重新烧固件。

**结论：用 AT 固件的 ESP8266 接阿里云 IoT，工程上不划算。** 题目里"EMQX/阿里云"是二选一，**选 EMQX**。

### 本地服务器：两条路

| 做法 | 改动 |
|---|---|
| **本地装个 EMQX** | 和上面完全一样，只是把 host 改成电脑的局域网 IP（比如 `192.168.1.100`）。**推荐**——零代码改动 |
| **自己写 TCP 服务器** | 要用 `AT+CIPSTART="TCP","<ip>",<port>` + `AT+CIPSEND=<len>` + 数据。⚠️ **现有驱动里没有这两个函数**，要照 `ESP8266_MQTT_Publish()` 的写法新增。而且 `AT+CIPSEND` 是**两步式交互**（先发长度、等 `>` 提示符、再发数据），比 MQTT 那条指令麻烦 |

**推荐：本地或公网 EMQX。** 题目说的"云端或本地服务器"，EMQX 两边都能当。

⚠️ 如果 EMQX 装在公网服务器上，**注意 1883 端口默认是明文的**，没有 TLS。题目4 只是作业演示，这样够用；要上生产再说。
