## 一、作用原理

### 天问模块是什么

天问（ASRPRO）是一颗**自带语音识别能力的模块**，本质是"MCU + 麦克风前端 + 离线语音识别固件"。它自己完成"听到人说话 → 识别出是哪条指令"的全部工作，然后**通过串口把识别结果告诉主控 MCU**。

关键点：**主控 MCU 完全不碰音频**。不认识拼音、不做 FFT、不训练模型。它只做两件事：

1. 从串口收 6 个字节；
2. 按协议翻译成动作。

这就是它和"用麦克风 + ADC + 自己跑识别算法"的根本区别——**语音识别的复杂度被模块吃掉了**，MCU 侧的工作量约等于"串口收包"。

### ⚠️ 先分清两件事：U5 是模块，**P1 才是喇叭**

看网表：

```
天问语言模块 ; U5
CONN-TH_XY301V-A-5.0-2P ; P1        ← 2 脚螺丝端子
5V ; U1.18 U5.15                     ← U5 用 5V 供电
'$1N90' ; P1.1 U5.1
'$1N91' ; P1.2 U5.2                  ← U5 的 1、2 脚接 P1
```

`P1` 是 **2 位 5.0 mm 间距的螺丝接线端子**，`U5.1` / `U5.2` 是模块的**喇叭输出**。**你的喇叭是外接插到 P1 上的，不是焊在板上的**。这个模块本身只有麦克风和识别芯片，**不发出声音**——发声靠外接喇叭。

所以：
- 如果你的板子接上电后没声音，**先确认 P1 上插了喇叭**，这不是代码问题；
- `U5.15` 接 5V、`U5.7` / `U5.16` 接 GND。**模块要 5 V**，这是全板唯一用 5 V 的器件（和 MCU 的 3.3 V 不是一个电源域），所以 U5 的输出电平是 5 V 逻辑——但 STM32F1 的 PA9/PA10 是 **5 V 容忍**的，能直接接，**不需要电平转换**。

### 通信协议：6 字节定长帧

天问模块向串口吐的是固定 6 字节：

```
字节:  [0]    [1]    [2]    [3]     [4]     [5]
含义:  帧头0  帧头1  长度   命令    数据    校验
值:    0x55   0xAA   0x02   cmd     data    xor
```

- **帧头** `0x55 0xAA`——两个固定字节，用来在字节流里找到帧的开头；
- **长度** `0x02`——后面 `cmd + data` 两个字节是有效载荷。参考工程里这个字节**收了但没检查**；
- **命令**（`cmd`）——识别结果的编号，参考工程用了 1~7；
- **数据**（`data`）——附加参数，比如"亮度调到 5 档"里的那个 `5`，或者"开/关"里的 `1`/`0`；
- **校验**——前 5 个字节**逐字节异或（XOR）**的结果。用来判断这一帧有没有被干扰。

举例：`55 AA 02 01 01 FD` 表示"命令 1，数据 1"（参考工程里 = 开灯）。验算：

```
0x55 ^ 0xAA = 0xFF
0xFF ^ 0x02 = 0xFD
0xFD ^ 0x01 = 0xFC
0xFC ^ 0x01 = 0xFD      ← 等于字节[5]，校验通过
```

**为什么用 XOR 而不是更"高级"的 CRC？** 因为够用。这个串口就在板子上、线长几厘米，电磁环境干净，XOR 已经能把绝大多数误码拦下来，而且**算得快**（5 次异或，几个周期）。CRC16 要查表或者移位循环，在这个场景下是过度设计。

### 参考工程的命令表

`Asrpro()` 里的 `switch (Usart3_RxPacket[3])`：

| cmd | 含义 | data 的作用 |
|---|---|---|
| 1 | 控制 LED 开关 | 1=开，0=关 |
| 2 | 控制风扇开关 | 1=开，0=关 |
| 3 | 控制步进电机（窗帘） | 1=正转（开），0=反转（关） |
| 4 | 切换系统模式 | 1=自动，0=手动 |
| 5 | 设置 LED 亮度档位 | 0~10，**乘以 10** 得到占空比百分比 |
| 6 | 设置风扇速度档位 | 0~10（参考工程里 0~10 对应的是 0/15/20/30/40/50/60/70/80/90/100，**不是等差的**）|
| 7 | 控制加湿器继电器 | 1=开，0=关 |

⚠️ **cmd 5/6 的 data 是"档位"不是"百分比"**。`data = 5` 意思是"第 5 档"，不是"50%"。cmd 5 里恰好 `5 × 10 = 50%`，cmd 6 里却是查表映射——**两个 cmd 的映射规则不一样**，照抄的时候别搞混。

⚠️ 还有一个设计细节：**cmd 1/2/3/6/7 都套了一层 `if (!systemState.mode)`**，也就是"只有手动模式才响应"。自动模式下这些命令被**静默忽略**。你这是有意的——自动模式下设备由传感器阈值驱动，不能让一句语音把它打断。移植时**保留这个语义**（或者你自己决定），但要知道这个 `if` 的存在，否则调试时会出现"语音说了没反应"的困惑。

## 二、代码原理

### 参考工程的中断状态机

`USART3_IRQHandler()` 是一个**三状态的状态机**，逐字节喂进去：

```
状态 0: 收到 0x55 → 存下, 进状态 1        (收到别的 → 留在状态 0)
状态 1: 收到 0xAA → 存下, 进状态 2        (收到别的 → 回状态 0, 指针清零)
状态 2: 收到任意字节都存下, 计数 +1
        计数满 6 → 算 xor 校验
                   校验通过 → 置 Usart3_RxFlag = 1（告诉主循环"有完整帧了"）
                   校验失败 → 回状态 0
```

**这个设计好在哪：**

1. **抗粘包/丢字节。** 如果中途掉了一个字节，状态机会自动回到状态 0 重新找 `0x55`，**不会永久错位**。如果用"收满 6 个再检查帧头"的朴素写法，一旦错位就永远收不对了。
2. **抗噪声。** 随便来一个字节不会破坏状态——只有在状态 0 收到 `0x55` 才启动，收到别的一律继续等。所以**不需要给 RX 加上拉电阻**：即使 `PA10` 悬空拾噪，噪声组成合法帧（5 个字节全对 + XOR 恰好匹配）的概率极低。

**`Usart3_RxFlag` 这个标志位是精髓**：中断里**只负责收**，不做任何动作；主循环 `while(1)` 里看到标志位再执行。这叫"中断尽量短"——中断里多花一个微秒，别的中断就多等一个微秒。参考工程的 `Asrpro()` 之所以能写成一大坨 `switch`，就是因为这份开销全在**线程上下文**里，不在中断里。

### 参考工程的一个死变量：`Usart3_seshig`

`System/Usart3.c` 里除了正常的收发变量，还多了一个：

```c
uint8_t Usart3_RxPacket[10];    // 数组开 10, 但只用前 6 个
uint8_t Usart3_RxFlag;
uint8_t Usart3_seshig;          // ← 从名字看是"是否"的拼音, 全工程没有任何地方读它
```

⚠️ `Usart3_seshig = 66;` 在中断里被赋值，然后**再也没人用它**。这是从别的工程抄过来的残渣。移植时**删掉**。

### 第二处要留意的地方：状态 2 里没有显式的越界检查

```c
case 2:
    Usart3_RxPacket[pRxPacket] = Res;
    pRxPacket++;
    if (pRxPacket >= 6) { ...校验... 清零... }
    break;
```

`pRxPacket` 到 5 就清零了，所以**正常情况下最多写到 `[5]`**，数组开 10 够用，**不会越界**。逻辑是对的，只是靠"计数到了就清零"这个不变量在保证，读的时候要自己捋一遍才放心。

### 参考工程的接收是阻塞式中断 + 裸机主循环

参考工程 `while(1)` 里直接调 `Asrpro()`，`Asrpro()` 一进来就检查 `Usart3_RxFlag`。这在裸机下没问题，**但在 FreeRTOS 下不能这么干**——任务里不能忙等标志位，得用"阻塞等待"。有两种写法：

**写法 A：标志位 + 短轮询（简单，推荐）**

```c
if (g_asrFlag)      /* 中断里置位 */
{
    g_asrFlag = 0;
    Asrpro();       /* 执行动作 */
}
vTaskDelay(pdMS_TO_TICKS(50));      /* 50ms 轮询一次, 完全不占 CPU */
```

好处：**中断里完全不碰 FreeRTOS API**，不需要考虑优先级问题；坏处：最坏延迟 50 ms，语音响应慢一点点——**人耳根本感觉不到**。

**写法 B：中断里通知任务（正规，但有限制）**

```c
/* 中断里 */
BaseType_t woken = pdFALSE;
vTaskNotifyGiveFromISR(g_asrTask, &woken);
portYIELD_FROM_ISR(woken);

/* 任务里 */
ulTaskNotifyTake(pdTRUE, portMAX_DELAY);
Asrpro();
```

好处：零延迟唤醒。**但有一条硬规矩**：调用 `...FromISR` 的中断，**NVIC 优先级数值必须 ≥ `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY`**（本工程是 5）。

`FreeRTOSConfig.h` 里的定义：

```c
#define configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY   5
#define configLIBRARY_LOWEST_INTERRUPT_PRIORITY        15
```

也就是 USART1 的中断优先级**只能设成 5~15**。如果设成 0~4，`...FromISR` 会触发断言（`configASSERT` 打开时直接死循环）。这个坑很隐蔽——**优先级"越高"（数值越小）反而越危险**。

⚠️ 还要注意 **DHT11 的干扰**：`BSP/dht11/dht11.c:147` 在读温湿度期间会调 `__disable_irq()` 把**全局中断关掉约 4 ms**。如果天问模块正好在这 4 ms 里发帧，**这一帧就丢了**（USART1 没有 DMA，DMA 通道 6 归了 ESP8266）。丢一帧的后果是"这句话没说上"，用户再喊一遍就行，可以接受。但如果发现语音**经常**失灵，可以试试把天问的帧做重发（在 ASRPRO 那边改，不是 MCU 侧的事），或者把 DHT11 的临界区缩短。

## 三、怎么移植到 PCB

### 第 0 步：先想清楚 printf 和天问怎么共存（本篇唯一的真正难题）

**硬事实**：网表里 `PA9 ; U1.6 U5.13`、`PA10 ; U1.7 U5.14`——天问模块的 TX/RX **焊死在 USART1 上**，而 `EnvMon_WIFI` 的 USART1 现在是调试 printf 口（`main.c` 里 `fputc` 重定向到 `huart1`）。

三条出路，**推荐第一条**：

#### 方案一（推荐）：共享 USART1，单向调试

**PA9（MCU 的 TX）同时接天问模块的 RX 和调试助手的 RX**，两个都是输入，谁也不会把线拉坏。USART1 的波特率 115200 保持不变。

为什么这样是安全的，有两个理由：

1. **printf 的输出永远不会被天问状态机误判成帧头。** 帧头要求 `0x55 0xAA`。`0x55` 是 `'U'`（ASCII 可打印），但 **`0xAA` 不是任何 ASCII 字符**，而 printf 输出的全是 ASCII。想让状态机从 0x55 走到 0xAA 是不可能的——它会在收到 `0x55` 后的下一个字节发现不是 `0xAA`，退回状态 0。**所以 printf 刷屏刷得再欢，也不会伪造出一条指令。**
2. **天问模块不会理睬 printf 的字节流。** 模块内部也有自己的帧解析，同样的道理，printf 的 ASCII 流形不成合法帧。

**代价和规矩**：

> ⚠️ **调试助手的 TX 绝对不能接到 PA10 上**，除非把天问模块先拔掉。因为 PA10 上已经有天问模块的 TX 在驱动了，两个输出顶在一起会互相干扰（严重时可能损坏 IO）。**调试助手只能单向"听"。**

如果你在调试期需要"从电脑发数据给 MCU"（比如做命令行调试），那就在代码里加个开关（比如上电时读某个 GPIO 或者一个 `#define`），选择"USART1 收的是天问数据"还是"USART1 收的是调试命令"，**不要物理上同时接**。

#### 方案二：放弃 printf

把 `fputc` 改到别的串口（要飞线，因为网表里没有第二个空闲 USART 引脚），或者干脆删掉 printf。**不推荐**——调试期没有 printf 会痛苦十倍，而且 OLED 屏虽然能显示，但看不到时序性的日志。

#### 方案三：飞线到 USART3

PB10/PB11 在网表里是**引出来了但悬空的**（`PB10 ; U1.35`、`PB11 ; U1.36`）。从模块的 TX/RX 飞两根线到 PB10/PB11，USART3 专职语音，USART1 专职 printf，**两条路彻底分开**。

这是**最干净的方案**，代价是两根飞线 + 要在 CubeMX 里加一路 USART3（或者手写初始化）。

> **建议**：先用方案一跑通验证逻辑，如果以后觉得别扭再改方案三。方案一的代码和方案三的**只差引脚宏和 `USARTx` 实例名**，改起来是十分钟的事。

**下面按方案一写。**

### 第 1 步：开 USART1 的接收中断

⚠️ `EnvMon_WIFI` 的 `Core/Src/usart.c` 里，**只有 USART2 开了 NVIC**（因为 `HAL_UART_Transmit_IT` 需要它），**USART1 完全没开**。天问要收数据，必须加上。

在 `Core/Src/usart.c` 的 `HAL_UART_MspInit()` 里，找到 USART1 那一段的 `USER CODE BEGIN USART1_MspInit 1`：

```c
  /* USER CODE BEGIN USART1_MspInit 1 */

    /* 天问语音模块要在 USART1 上收帧, 必须开 NVIC.
     * 优先级 6: 必须 >= configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY(5),
     * 否则中断里调 FreeRTOS 的 ...FromISR API 会踩断言.
     * 插在 USER CODE 段内, CubeMX 重新生成代码时不会被冲掉. */
    HAL_NVIC_SetPriority(USART1_IRQn, 6, 0);
    HAL_NVIC_EnableIRQ(USART1_IRQn);

  /* USER CODE END USART1_MspInit 1 */
```

在 `Core/Src/stm32f1xx_it.c` 里加中断服务函数（照抄现有 `USART2_IRQHandler` 的格式）：

```c
void USART1_IRQHandler(void)
{
  /* USER CODE BEGIN USART1_IRQn 0 */
  Asr_RxByteFromISR();          /* 逐字节喂给帧状态机 */
  /* USER CODE END USART1_IRQn 0 */
  HAL_UART_IRQHandler(&huart1);
  /* USER CODE BEGIN USART1_IRQn 1 */
  /* USER CODE END USART1_IRQn 1 */
}
```

并在 `Core/Inc/stm32f1xx_it.h` 的 `/* Exported functions prototypes */` 段加一行声明：

```c
void USART1_IRQHandler(void);
```

⚠️ **`stm32f1xx_it.c` 顶部有警告说重新生成会冲掉东西**，所以像上面这样挂在 `USER CODE` 段里最保险。

⚠️ 现在 `System/Usart3.c` 那个中断是自己直接读 DR 的（SPL 风格）。**在 HAL 下不要这么干**——HAL 的 `HAL_UART_IRQHandler(&huart1)` 已经会读 DR 并清标志了，如果你在它之前又读一次，**字节就被你吃掉了**，HAL 拿到的是空的。

所以正确做法是把"取字节"这件事做成一个 `HAL_UART_RxCpltCallback`，或者更简单地直接读 DR：

**做法 A（推荐，最简单）**：在中断里直接读 DR，然后**不要**再调 `HAL_UART_IRQHandler`：

```c
void USART1_IRQHandler(void)
{
  if (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_RXNE))
  {
    Asr_RxByteFromISR((uint8_t)(huart1.Instance->DR & 0xFFU));   /* 读 DR 顺手清标志 */
  }
}
```

**做法 B（HAL 风格）**：开一个 1 字节的 `HAL_UART_Receive_IT(&huart1, &b, 1)`，在 `HAL_UART_RxCpltCallback()` 里处理，然后**再挂一次** `HAL_UART_Receive_IT`：

```c
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
  if (huart->Instance == USART1)
  {
    Asr_RxByteFromISR(g_asrByte);
    HAL_UART_Receive_IT(&huart1, &g_asrByte, 1);   /* 必须重挂, HAL 是单次的 */
  }
}
```

⚠️ 做法 B 有个出名的坑：**必须重挂**，忘了这一步就只收得到第一个字节（`HAL_UART_Receive_IT` 不是循环的）。而且回调里再调 `HAL_UART_Receive_IT` 有可能因为 `gState` 状态没归位而返回 `HAL_BUSY`——HAL 的 `UART_Receive_IT` 是在清 RXNE 之后调回调的，所以正常没问题，但这是 HAL 的已知玻璃边。

**本篇的示例代码用做法 A**——它更短、更可控，和参考工程的写法贴得更近。

⚠️ 还有一个：`HAL_UART_IRQHandler` 里还会处理 **ORE（溢出错误）**。做法 A 不调它，所以如果字节来得太快吃不下，**ORE 标志不会自动清**，串口可能卡死。本工程的场景下（每帧 6 字节，命令间隔至少几百毫秒）不会溢出，**可以不处理**。但如果你发现收了几帧之后彻底收不到了，就是这个问题，在中断里补一句：

```c
if (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_ORE)) { __HAL_UART_CLEAR_OREFLAG(&huart1); }
```

### 第 2 步：`BSP/asr/asr.h`

```c
#ifndef __ASR_H
#define __ASR_H

#include "main.h"

/* 天问模块接在 USART1(PA9/PA10) 上, 和 printf 共用一路 —— 见 04 篇 */
#define ASR_UART    huart1

/* 6 字节定长帧: 0x55 0xAA len cmd data xor */
#define ASR_FRAME_LEN   6U

/* 命令码 (对应天问模块里配的识别项) */
#define ASR_CMD_LED        1U
#define ASR_CMD_FAN        2U
#define ASR_CMD_MOTOR      3U
#define ASR_CMD_MODE       4U
#define ASR_CMD_LED_LEVEL  5U
#define ASR_CMD_FAN_LEVEL  6U
#define ASR_CMD_HUMID      7U

void    Asr_Init(void);
void    Asr_RxByteFromISR(uint8_t byte);   /* 只在 USART1 中断里调 */
uint8_t Asr_RxFlag;                        /* 1 = 收到一个校验通过的新帧 */
uint8_t Asr_RxPacket[ASR_FRAME_LEN];

#endif
```

### 第 3 步：`BSP/asr/asr.c`

```c
/* ============================================================================
 * 天问语音模块 (ASRPRO) 帧解析
 * 帧格式: 0x55 0xAA 0x02 cmd data xor, 校验 = 前 5 字节异或
 * 三状态机: 只在状态 0 收 0x55 才启动, 中途错位自动回状态 0 重新找帧头
 * 中断里只收不发, 动作留给任务做
 * ========================================================================== */

#include "asr.h"

uint8_t Asr_RxPacket[ASR_FRAME_LEN];
uint8_t Asr_RxFlag;

static uint8_t Asr_CalXor(const uint8_t *data, uint32_t len)
{
    uint8_t sum = 0U;
    uint32_t i;

    for (i = 0; i < len; i++)
    {
        sum ^= data[i];
    }
    return sum;
}

/* 逐字节状态机, 只被 USART1 中断调用 */
void Asr_RxByteFromISR(uint8_t byte)
{
    static uint8_t state = 0U;      /* 0=等0x55 1=等0xAA 2=攒数据 */
    static uint8_t idx   = 0U;

    switch (state)
    {
        case 0U:
            if (byte == 0x55U) { Asr_RxPacket[idx++] = byte; state = 1U; }
            break;

        case 1U:
            if (byte == 0xAAU) { Asr_RxPacket[idx++] = byte; state = 2U; }
            else               { idx = 0U; state = 0U; }
            break;

        case 2U:
            Asr_RxPacket[idx++] = byte;
            if (idx >= ASR_FRAME_LEN)
            {
                if (Asr_CalXor(Asr_RxPacket, ASR_FRAME_LEN - 1U) == Asr_RxPacket[ASR_FRAME_LEN - 1U])
                {
                    Asr_RxFlag = 1U;    /* 交给任务去处理 */
                }
                idx = 0U;
                state = 0U;
            }
            break;

        default:
            idx = 0U;
            state = 0U;
            break;
    }
}

void Asr_Init(void)
{
    /* USART1 已由 MX_USART1_UART_Init() 配好, 这里只负责打开接收中断.
     * 直接读 DR 的方式, 不用 HAL_UART_Receive_IT, 见 04 篇第 1 步. */
    __HAL_UART_ENABLE_IT(&ASR_UART, UART_IT_RXNE);
}
```

⚠️ **状态机里那两个 `static` 变量在中断上下文里是安全的**——USART1 的中断不可能重入（同一个中断源在 ISR 执行期间被屏蔽）。但**绝对不要**在任务里也去调 `Asr_RxByteFromISR()`，那就会出现两个上下文同时改 `state` 的竞态。

### 第 4 步：写语音任务

**关键设计**：`Asrpro()` 那一大坨 `switch` 是**业务逻辑**，不是驱动。所以要拆开——帧解析归 `BSP/asr/`，动作执行归 `APP/task_asr.c`。

这样拆的好处是：以后换成别的语音模块（只要协议一样），驱动换掉、`task_asr.c` 不用动；换了产品需求（比如语音要控制继电器），只改 `task_asr.c`。

按你板子上**实际有的外设**，参考工程的 7 条命令要裁剪成这样：

| cmd | 参考工程的动作 | 你的板子上 |
|---|---|---|
| 1 | LED 开关 | ✅ 用 `LED1_On/Off` |
| 2 | 风扇开关 | ❌ 没风扇 → 改成 `LED2_On/Off`（或删掉） |
| 3 | 步进电机 | ❌ 没有 → **删掉** |
| 4 | 切换自动/手动 | ✅ 保留（但你的工程没有自动模式，见下） |
| 5 | LED 亮度 0~10 | ❌ 没有 PWM → 改成"开/关"或**删掉** |
| 6 | 风扇速度 | ❌ **删掉** |
| 7 | 加湿器 | ❌ 没有 → **删掉** |

**你的板子能做的语音控制只有**：LED1 开关、LED2 开关、蜂鸣器开关。**就这三条**，别硬凑。

⚠️ 再说明一次：**这张表是"收"的方向**——人对着模块说话，模块发帧给 MCU。题目4 必做3 要的"播报"是相反的，见 [06 篇第四节](06-题目4缺口补齐-按键时间播报PWM云端.md)。

`APP/task_asr.c`：

```c
/* ============================================================================
 * 语音命令执行任务: 天问模块识别出指令 → 这里翻译成具体动作
 * 帧解析在 BSP/asr/asr.c, 本文件只管"命令码 → 干什么"
 * ========================================================================== */

#include "task_asr.h"
#include "app_main.h"
#include "asr.h"
#include "led.h"
#include "buzzer.h"
#include <stdio.h>

static void Asr_Handle(void)
{
    uint8_t cmd  = Asr_RxPacket[3];
    uint8_t data = Asr_RxPacket[4];

    switch (cmd)
    {
        case ASR_CMD_LED:                       /* "开灯" / "关灯" */
            if (data) { LED1_On(); } else { LED1_Off(); }
            printf("[ASR] LED %s\r\n", data ? "ON" : "OFF");
            g_oledData.led1 = data;             /* 顺手上屏 */
            break;

        case ASR_CMD_FAN:                       /* 板上没风扇, 借用 D3 演示 */
            if (data) { LED2_On(); } else { LED2_Off(); }
            printf("[ASR] LED2 %s\r\n", data ? "ON" : "OFF");
            g_oledData.led2 = data;
            break;

        case ASR_CMD_MODE:                      /* "自动模式" / "手动模式" */
            printf("[ASR] MODE %s\r\n", data ? "AUTO" : "MANUAL");
            break;

        case ASR_CMD_HUMID:                     /* 板上没加湿器, 拿蜂鸣器演一下 */
            if (data) { Buzzer_On(); } else { Buzzer_Off(); }
            printf("[ASR] BUZZER %s\r\n", data ? "ON" : "OFF");
            break;

        default:
            printf("[ASR] unknown cmd=%u data=%u\r\n", cmd, data);
            break;
    }
}

void TaskAsr(void *argument)
{
    Asr_Init();

    for (;;)
    {
        if (Asr_RxFlag)
        {
            Asr_RxFlag = 0;
            Asr_Handle();
        }

        vTaskDelay(pdMS_TO_TICKS(APP_ASR_PERIOD_MS));   /* 50ms 轮询, 零 CPU 占用 */
    }
}

void TaskAsrCreate(void)
{
    if (xTaskCreate(TaskAsr, "Asr",
                    APP_STACK_ASR, NULL,
                    APP_PRIO_ASR, NULL) != pdPASS)
    {
        printf("ERROR: create ASR task failed\r\n");
        Error_Handler();
    }
}
```

`APP/task_asr.h` 照别的一模一样：`#include "FreeRTOS.h"` / `task.h`，声明 `TaskAsr` 和 `TaskAsrCreate`。

**`APP/app_main.h` 里加**：

```c
#define APP_ASR_PERIOD_MS   50       /* 语音响应延迟上限, 人感觉不到 */
#define APP_PRIO_ASR        1        /* 和 OLED 同档: 不急, 但不能比采集低 */
#define APP_STACK_ASR       256

/* OledData 里多加两个字段 */
uint8_t led1;
uint8_t led2;
```

**`APP/app_main.c`**：

```c
TaskWifiCreate();
TaskDht11Create();
TaskLightCreate();
TaskOledCreate();
TaskAsrCreate();          /* ← 新增 */
```

⚠️ **为什么用 50 ms 轮询而不是中断直接唤醒任务**：见第二节"写法 A / 写法 B"的对比。轮询版本**中断里完全不碰 FreeRTOS**，省掉了优先级那一整类坑，而且 50 ms 的延迟人耳感知不到。这是"最短能跑通"的选择。

⚠️ **别把 `APP_ASR_PERIOD_MS` 设成 0 或者 1**。那样 `vTaskDelay(0)` 等于不延时，任务变成忙等，会把 CPU 吃光——现象是 WiFi 连不上、OLED 不刷新，但串口还在疯狂打印。

### 第 5 步：验证

**分三段验，别一次全上。**

**第一段：先确认模块活着。** 天问模块一般上电后要么播报一段提示音（从 P1 的喇叭出来），要么串口吐一串启动信息。**如果插了喇叭什么都没听到，别往下走**——先查 5 V 供电（`U5.15`）和 GND（`U5.7`/`U5.16`），以及 P1 上到底插没插喇叭。

**第二段：不做任何解析，先看原始字节。** 在 `TaskAsr` 里把 `Asr_Handle()` 换成打印：

```c
printf("raw: %02X %02X %02X %02X %02X %02X\r\n",
       Asr_RxPacket[0], Asr_RxPacket[1], Asr_RxPacket[2],
       Asr_RxPacket[3], Asr_RxPacket[4], Asr_RxPacket[5]);
```

对着模块说"开灯"，应该看到 `55 AA 02 01 01 FD`。

- **什么都没打**：中断没进来。查 `HAL_NVIC_EnableIRQ(USART1_IRQn)` 有没有加、`USART1_IRQHandler` 有没有写、`stm32f1xx_it.h` 里声明了没。
- **打出来是乱的、帧头不对**：**波特率不对**。天问模块的串口波特率是在**它的固件里配的**——参考工程的 `System/Usart3.c` 里写的是 **9600**，而你的 USART1 现在是 **115200**。**两边必须一致**。推荐去天问 Block 里把模块改成 115200（这样 printf 不受影响），详见 [06 篇第四节](06-题目4缺口补齐-按键时间播报PWM云端.md)。
- **帧头对但字节不对**：接线问题。`U5.13`（模块的某个串口脚）连的是 `PA9`（MCU 的 **TX**）。如果天问模块把"TX"标成发送脚，那它接的应该是 MCU 的 RX——**接反了就会收到全 0 或者乱码**。这根线在 PCB 上焊死了，如果确认接反，只能割线飞线。

**第三段：接上动作。** 恢复 `Asr_Handle()`，说"开灯"，D2 应该点亮（`printf` 会打 `[ASR] LED ON`）。

**两个最容易踩的坑：**

1. **`data` 是 0 还是 1 搞反了。** 参考工程里 `if (Usart3_RxPacket[4])` = "非 0 就是开"。如果你的天问固件里"关灯"发的是 `data = 2` 而不是 0，那这句判断就永远为真，灯永远关不掉。**先用第二段的原始打印把每个命令的实际字节都记下来，再写 `switch`。**
2. **命令码和天问固件里的对不上。** `cmd` 是**天问模块固件里配的**（在它的图形化编程界面里给每条语音指令分配一个编号），不是协议规定的。参考工程的 1~7 只对**参考工程那份固件**有效。**你的模块刷的是哪份固件，就只有那份的命令表**。所以第二段那个"把所有命令的真实字节抄下来"的步骤是必须做的，不能跳。
