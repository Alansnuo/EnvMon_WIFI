# 01 BH1750 光照传感器移植

**定位**：把参考工程的 GY-302/BH1750 软件 I2C 驱动，从 PB4/PB5 改成 PB6/PB7，用 HAL 重写，接进 FreeRTOS。

**读之前先补**：[00-总纲](00-总纲-PCB引脚表与移植决策.md)（尤其是"机制二：微秒延时"和"机制三：任务优先级/栈"）。

**参考文件**：`1.源代码（面包板可用）/Hardware/BH1750.h`、`BH1750.c`

---

## 一、作用原理

### 这个模块是干什么的

BH1750 是一颗**数字环境光强度传感器**，输出的直接就是**照度 lux**，不是电压。这点是本篇最重要的前提——它和光敏电阻那种"给个模拟电压让你自己去 ADC"的东西完全不同。

GY-302 是把 BH1750 芯片 + 上拉电阻 + 电平转换做在一块小板上，引出 4 个脚：VCC / GND / SCL / SDA。你的网表里 `U6` 就是它。

### 它凭什么能量出 lux

核心是一个**光谱响应接近人眼**的光电二极管。芯片内部把光电流做积分，再用一个固定的换算系数输出数字量：

```
lux = 原始计数值 / 1.2
```

这个 `1.2` 就是参考工程 `read_BH1750()` 里 `dis_data / 1.2` 的来历。量程 0~65535 lx（16 位原始值），分辨率 1 lx。

它还支持两种分辨率模式：

| 模式 | 指令 | 转换时间 | 分辨率 |
|---|---|---|---|
| 连续 H 分辨率 | `0x10` | 120 ms 典型 / 180 ms 最大 | 1 lx |
| 连续 L 分辨率 | `0x13` | 16 ms 典型 | 4 lx |

参考工程用的是 `0x10`，所以后面要 `Delay_ms(180)`。

### 和 MCU 怎么通

**标准 I2C，从机地址 0x23**（7 位）。写操作时地址字节是 `0x23 << 1 = 0x46`，读操作是 `0x47`。GY-302 板上把 ADDR 脚接地，所以地址就是 0x23，参考工程里的 `SlaveAddress 0x46` 是对的，**移植时不用改**。

流程极简：

```
写 0x01 (上电)  →  写 0x10 (选 H 分辨率模式)  →  等 180ms  →  读 2 字节  →  除以 1.2
```

和 OLED 那种要发一大堆初始化命令的屏比起来，BH1750 简单得多。

### ⚠️ GY-302 必须带上拉

I2C 是**开漏总线**：所有器件只能把线拉低，不能拉高，靠上拉电阻把线拉回高电平。GY-302 小板**已经焊好了 4.7 kΩ 上拉**，不用你外加。但如果你后面想把这颗芯片直接贴到主板上去掉小板，**上拉必须自己补**，否则总线永远是高不起来的死线。

## 二、代码原理

### 参考工程的软件 I2C 是怎么实现的

STM32F103 有硬件 I2C，但这里没用——参考工程是**用两个普通 GPIO 手动模拟 I2C 时序**（bit-bang）。原因很现实：F1 的硬件 I2C 有出名的死锁 bug，社区里一地鸡毛，所以这套教程代码统一用软件 I2C。

软件 I2C 的全部内容就是四个原子动作，其余所有函数都是它们的组合：

```c
/* 参考工程 BH1750.c，四个原始动作 */
void BH1750_Start()   // SDA 高 SCL 高 → SDA 拉低（SCL 高时 SDA 下降沿 = 起始）
void BH1750_Stop()    // SDA 低 SCL 高 → SDA 拉高（SCL 高时 SDA 上升沿 = 停止）
void BH1750_SendACK() // 主机把 SDA 拉低/拉高，再打一个时钟，表示应答/非应答
int  BH1750_RecvACK() // 主机释放 SDA，打一个时钟，读 SDA 电平 = 从机有没有应答
```

注意 `Start` 和 `Stop` 的定义：**起始/停止不是靠电平高低，而是靠"SCL 为高的时候 SDA 跳变"**。这是 I2C 协议最容易记混的一点——正常传数据时 SDA 只允许在 SCL 为低的时候变，只有在 SCL 为高时变化才被解读成起始/停止。

### 参考工程的一个真 bug：SDA 是推挽输出

看 `BH1750_SendACK()` 和 `BH1750_RecvACK()`：

```c
GPIO_InitStruct.GPIO_Mode = GPIO_Mode_Out_PP;   /* 推挽 */
...
GPIO_InitStruct.GPIO_Mode = GPIO_Mode_IPU;      /* 上拉输入 */
```

参考工程在**推挽输出**和**上拉输入**之间来回切换 `GPIO_Init`。

上拉输入那一半是对的（读的时候必须放手）。但**推挽输出是错的**：I2C 要求开漏输出。危害在于收 ACK 的瞬间——主机把 SDA 用推挽驱动到高电平，同时从机正在把 SDA 拉低表示"我应答了"，**两个管子直接对顶**。面包板上它确实能跑（F1 的驱动能力不强，顶一会儿不至于烧），但这是实打实的电气违规，长期跑会加速老化，换到你的 PCB 上更不该留。**移植时必须改成开漏。**

### 参考工程第二个问题：`mread()` 里的死代码

```c
for (i = 0; i < 3; i++)          // 只跑 0,1,2
{
    BUF[i] = BH1750_RecvByte();
    if (i == 3)                  // ← 永远不成立
    {
        BH1750_SendACK(1);       // 最后一次"非应答"永远发不出去
    }
    else
    {
        BH1750_SendACK(0);       // 三次全是应答
    }
}
```

`i` 最大到 2，`i == 3` 是死代码，**最后一个字节的 NACK 从没发出来**。BH1750 只需要 2 字节数据（`BUF[0]` 高 8 位、`BUF[1]` 低 8 位），`BUF[2]` 读的第三个字节其实没用上，还要多发一个 ACK 拖着总线。移植时直接砍成"读 2 字节，最后一个发 NACK"。

### 第三个隐患：读失败会返回一个"看起来正常"的数

`read_BH1750()` 在总线断线/器件没应答时，读回来的全是 `0xFF`，于是：

```
raw = 0xFFFF = 65535
lux = 65535 / 1.2 = 54612
```

**不会报错，只会返回 54612**。如果是全 0，则返回 0。这两个数就是"总线挂了"的标志值。参考工程里没做判断，上游 `SensorScan()` 直接把它塞进 `sensorData.lux` 拿去和阈值比。你移植后如果在串口里看到 lux 恒定 54612 或者恒定 0，**第一反应应该是查线，不是查传感器**。

## 三、怎么移植到 PCB

### 第 0 步：先加微秒延时（没有它软件 I2C 根本跑不起来）

参考工程用的是 `Delay_us()`（SPL 忙等），`EnvMon_WIFI` **没有这个函数**。往 `BSP/bsp_delay/` 里补一个公用的，用 DWT 周期计数器实现——和 `dht11.c` 里那份同理，不占 SysTick、不占 TIM、和 FreeRTOS 零冲突。

**改哪几行**

`BSP/bsp_delay/bsp_delay.h`，加一行声明：

```c
void BSP_DelayMs(uint32_t ms);
void BSP_DelayUs(uint32_t us);      /* ← 新增: 微秒忙等, 只给总线时序用 */
```

`BSP/bsp_delay/bsp_delay.c`，加一个实现：

```c
/* ---------- 微秒忙等: DWT 周期计数器 ----------
 * 用途: 软件 I2C / 单总线这类要求 us 级延时的时序. 是纯忙等, 别拿它做毫秒级延时,
 *       那样会把 CPU 白占着不放给别的任务.
 * DWT 是 Cortex-M3 内核自带的, 和 SysTick/TIM 完全无关, 上了 FreeRTOS 也不冲突.
 * (和 BSP/dht11/dht11.c 里那份是各自独立的 static 变量, 两次初始化都只是把
 *  DEMCR.TRCENA 和 DWT.CTRL 置位, 幂等, 不会互相干扰.) */
static uint32_t s_cyc_per_us = 0U;      /* 0 = 还没初始化 */

void BSP_DelayUs(uint32_t us)
{
    uint32_t start;

    if (s_cyc_per_us == 0U)             /* 首次调用时按实际主频算, 省掉调用顺序的坑 */
    {
        s_cyc_per_us = HAL_RCC_GetHCLKFreq() / 1000000UL;
        CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;   /* DWT 总开关, 不开 CYCCNT 恒 0 */
        DWT->CYCCNT = 0UL;
        DWT->CTRL  |= DWT_CTRL_CYCCNTENA_Msk;
    }

    start = DWT->CYCCNT;                /* 向上计数, 无符号相减天然抗回绕 */
    while ((DWT->CYCCNT - start) < us * s_cyc_per_us) { }
}
```

**怎么验证**：先写一个临时任务，循环 `BSP_DelayUs(1000)` 一万次并把秒数 print 出来，应该是 10 秒左右。偏差 10% 以内都算正常（DWT 是 CPU 周期数，和主频严格对应，所以其实应该很准；如果差得离谱说明 `HAL_RCC_GetHCLKFreq()` 拿到的不是 72 MHz）。

### 第 1 步：新增驱动文件

新建 `BSP/bh1750/bh1750.h` 和 `bh1750.c`，把两个文件加进 Keil 工程（和 `BSP/dht11/` 并列）。

**`BSP/bh1750/bh1750.h`**

```c
#ifndef __BH1750_H
#define __BH1750_H

#include "main.h"

/* 软件 I2C 引脚 —— 对应 PCB 上 GY-302(U6): U6.3→PB6(SCL), U6.4→PB7(SDA) */
#define BH1750_SCL_PORT  GPIOB
#define BH1750_SCL_PIN   GPIO_PIN_6
#define BH1750_SDA_PORT  GPIOB
#define BH1750_SDA_PIN   GPIO_PIN_7

#define BH1750_ADDR_W    0x46          /* 0x23 << 1, GY-302 的 ADDR 脚接地 */

void  BH1750_Init(void);
float BH1750_ReadLux(void);

#endif
```

**改哪几行、改成什么**（和参考工程对照）

| 参考工程 | 改成 | 为什么 |
|---|---|---|
| `#define SDA PBout(5)` | `GPIO_PIN_7` | PCB 走 PB7 |
| `#define SCL PBout(4)` | `GPIO_PIN_6` | PCB 走 PB6 |
| `#define bh1750_PORT GPIOB` | 不变 | 还是 GPIOB |
| `#define SlaveAddress 0x46` | 不变 | 地址本来就是对的 |
| `Delay_us(5)` | `BSP_DelayUs(5)` | 见第 0 步 |
| `Delay_ms(180)` | `BSP_DelayMs(180)` | 见总纲机制一 |
| `GPIO_Mode_Out_PP` | `GPIO_MODE_OUTPUT_OD` | 推挽改开漏，见第二节 |
| `GPIO_PinRemapConfig(GPIO_Remap_SWJ_JTAGDisable, ENABLE)` | **删掉** | 那行是为了解放 PB4；PB6/PB7 不是 JTAG 脚，不需要 |

**`BSP/bh1750/bh1750.c`**

```c
/* ============================================================================
 * BH1750 光照传感器 (GY-302) 软件 I2C 驱动
 * 时序: 上电(0x01) → H分辨率模式(0x10) → 等180ms → 读2字节 → lux = raw/1.2
 * 两个 IO 都是开漏: 高电平=释放总线, 这样从机拉低应答时不会和主机对顶
 * ========================================================================== */

#include "bh1750.h"
#include "bsp_delay.h"

#define BH1750_HALF_US   5U             /* I2C 半周期, 手册不要求这么快, 取大不取小 */

#define SCL_H()   HAL_GPIO_WritePin(BH1750_SCL_PORT, BH1750_SCL_PIN, GPIO_PIN_SET)
#define SCL_L()   HAL_GPIO_WritePin(BH1750_SCL_PORT, BH1750_SCL_PIN, GPIO_PIN_RESET)
#define SDA_H()   HAL_GPIO_WritePin(BH1750_SDA_PORT, BH1750_SDA_PIN, GPIO_PIN_SET)
#define SDA_L()   HAL_GPIO_WritePin(BH1750_SDA_PORT, BH1750_SDA_PIN, GPIO_PIN_RESET)
/* 开漏模式下 IDR 读的是总线的真实电平, 不是 ODR, 所以能这么直接用 */
#define SDA_IN()  ((BH1750_SDA_PORT->IDR & BH1750_SDA_PIN) ? 1U : 0U)

static void BH1750_Start(void)
{
    SDA_H(); SCL_H(); BSP_DelayUs(BH1750_HALF_US);
    SDA_L();          BSP_DelayUs(BH1750_HALF_US);   /* SCL 为高时 SDA 下降沿 = 起始 */
    SCL_L();          BSP_DelayUs(BH1750_HALF_US);
}

static void BH1750_Stop(void)
{
    SDA_L();          BSP_DelayUs(BH1750_HALF_US);
    SCL_H();          BSP_DelayUs(BH1750_HALF_US);
    SDA_H();          BSP_DelayUs(BH1750_HALF_US);   /* SCL 为高时 SDA 上升沿 = 停止 */
}

/* 发一个字节并收从机应答: 返回 0 表示从机拉低了 SDA(有应答) */
static uint8_t BH1750_SendByte(uint8_t dat)
{
    uint8_t i, ack;

    for (i = 0; i < 8U; i++)
    {
        if (dat & 0x80U) { SDA_H(); } else { SDA_L(); }
        dat <<= 1;
        BSP_DelayUs(BH1750_HALF_US);
        SCL_H();
        BSP_DelayUs(BH1750_HALF_US);
        SCL_L();
    }

    SDA_H();                                    /* 先放手, 让从机有机会拉低 */
    BSP_DelayUs(BH1750_HALF_US);
    SCL_H();
    BSP_DelayUs(BH1750_HALF_US);
    ack = SDA_IN();
    SCL_L();
    BSP_DelayUs(BH1750_HALF_US);

    return ack;
}

/* 收一个字节; sendAck=1 时本级应答, 0 是末字节的非应答 */
static uint8_t BH1750_RecvByte(uint8_t sendAck)
{
    uint8_t i, dat = 0U;

    SDA_H();                                    /* 读之前必须先释放 SDA */
    for (i = 0; i < 8U; i++)
    {
        BSP_DelayUs(BH1750_HALF_US);
        SCL_H();
        BSP_DelayUs(BH1750_HALF_US);            /* 高电平中点采, 数据已稳定 */
        dat = (uint8_t)((dat << 1) | SDA_IN());
        SCL_L();
    }

    if (sendAck) { SDA_L(); } else { SDA_H(); }
    BSP_DelayUs(BH1750_HALF_US);
    SCL_H();
    BSP_DelayUs(BH1750_HALF_US);
    SCL_L();
    SDA_H();                                    /* 还回总线 */
    BSP_DelayUs(BH1750_HALF_US);

    return dat;
}

static void BH1750_WriteCmd(uint8_t cmd)
{
    BH1750_Start();
    BH1750_SendByte(BH1750_ADDR_W);
    BH1750_SendByte(cmd);
    BH1750_Stop();
}

void BH1750_Init(void)
{
    GPIO_InitTypeDef gpio = {0};

    __HAL_RCC_GPIOB_CLK_ENABLE();

    gpio.Pin   = BH1750_SCL_PIN | BH1750_SDA_PIN;
    gpio.Mode  = GPIO_MODE_OUTPUT_OD;           /* 开漏: GPIO_PIN_SET 等于"放手" */
    gpio.Pull  = GPIO_NOPULL;                   /* 上拉由 GY-302 小板上的 4.7k 提供 */
    gpio.Speed = GPIO_SPEED_FREQ_HIGH;
    HAL_GPIO_Init(BH1750_SCL_PORT, &gpio);

    SCL_H();
    SDA_H();                                    /* 空闲态: 两根都释放 */

    BH1750_WriteCmd(0x01);                      /* 上电 */
    BSP_DelayMs(10);
}

float BH1750_ReadLux(void)
{
    uint16_t raw;

    BH1750_WriteCmd(0x10);                      /* 连续 H 分辨率模式, 1 lx */
    BSP_DelayMs(180);                           /* 手册: 一次转换最长 180ms */

    BH1750_Start();
    BH1750_SendByte(BH1750_ADDR_W | 0x01U);     /* 读操作 */
    raw  = (uint16_t)((uint16_t)BH1750_RecvByte(1U) << 8);   /* 高字节, 主机应答 */
    raw |= (uint16_t)BH1750_RecvByte(0U);                    /* 低字节, 主机非应答 */
    BH1750_Stop();

    return (float)raw / 1.2f;
}
```

**和参考工程对照着看，改了什么**

1. **推挽 → 开漏**（电气正确性，见第二节）。副作用是"高电平"变成了"释放总线"，所以 `SDA_H()` 在开漏下同时兼顾了"输出高"和"当输入用"两种角色。
2. **不再切模式**。参考工程每读一字节都要 `GPIO_Init` 两次（`IPU` ↔ `PP`）——慢且啰嗦。开漏模式下 `IDR` 读到的就是总线真实电平（不是 `ODR`），**所以读的时候什么都不用切，直接 `SDA_IN()`**。这一下省掉了参考工程里 6 处 `GPIO_Init`。
3. **`mread()` 的循环砍掉**：只读 2 字节，末字节发 NACK（修掉那个 `i == 3` 死代码）。
4. **`Init_BH1750()` 里的 JTAG 重映射删掉**（PB6/PB7 不是 JTAG 脚）。
5. `read_BH1750()` 里那句多余的 `Single_Write_BH1750(0x01)`（每次测量都重新上电一次）也去掉了，上电在 `BH1750_Init()` 里做一次就够。

⚠️ 如果实测发现第 2 条在你的 HAL 版本上不成立——表现为 ACK **恒为 1**（永远读不到应答）或者恒为 0——退回到参考工程的写法：读之前 `gpio.Mode = GPIO_MODE_INPUT; gpio.Pull = GPIO_PULLUP; HAL_GPIO_Init(...)`，读完再切回 `GPIO_MODE_OUTPUT_OD`。逻辑不变，只是多两次 `HAL_GPIO_Init`。

### 第 2 步：写采集任务

`APP/task_light.c` 现在是**空占位**（只有一段注释），`TaskLightCreate()` 在头文件里声明了但没有任何地方定义。照 `APP/task_dht11.c` 的样子补上：

```c
/* ============================================================================
 * 光照采集任务: 每 2 秒读一次 BH1750, 通过队列交给 WiFi 任务上报
 * ========================================================================== */

#include "task_light.h"
#include "app_main.h"
#include "bh1750.h"
#include <stdio.h>

void TaskLight(void *argument)
{
    float lux;

    for (;;)
    {
        lux = BH1750_ReadLux();
        printf("[LIGHT] %.0f lx\r\n", lux);

        xQueueSend(g_xLightQueue, &lux, 0);     /* 满则丢, 和 DHT11 一样不阻塞 */

        vTaskDelay(pdMS_TO_TICKS(APP_LIGHT_PERIOD_MS));
    }
}

void TaskLightCreate(void)
{
    if (xTaskCreate(TaskLight, "Light",
                    APP_STACK_LIGHT, NULL,
                    APP_PRIO_LIGHT, NULL) != pdPASS)
    {
        printf("ERROR: create Light task failed\r\n");
        Error_Handler();
    }
}
```

`APP/task_light.h` 补上 `void TaskLight(void *argument);`。

```c
QueueHandle_t g_xLightQueue = NULL;

void App_Init(void)
{
    DHT11_Init();

    BH1750_Init();                                   /* ← 新增 */
    printf("BH1750 Sensor Ready!\r\n");              /* ← 新增 */

    g_xDht11Queue = xQueueCreate(APP_DHT11_QUEUE_LEN, sizeof(DHT11_Data));
    g_xLightQueue = xQueueCreate(APP_LIGHT_QUEUE_LEN, sizeof(float));   /* ← 新增 */

    TaskWifiCreate();
    TaskDht11Create();
    TaskLightCreate();                               /* ← 新增 */
}
```

⚠️ 几点要注意：

- **`BH1750_Init()` 放在 `vTaskStartScheduler()` 之前**（也就是 `App_Init()` 里）是对的，因为它内部有 `BSP_DelayMs(10)`——调度器没跑时 `BSP_DelayMs` 自动退回 `HAL_Delay` 忙等，没问题。这和 `DHT11_Init()` 是同一个机制（总纲机制一）。
- 两个任务都占 GPIOB，但用的是不同脚（DHT11 走 PB12，BH1750 走 PB6/PB7），**不冲突**。
- **不需要临界区**。软件 I2C 被任务切换打断是安全的：I2C 协议允许 SCL 低电平任意长（时钟拉伸），被打断只是把这一位的时间拉长，从机不会超时。加 `taskENTER_CRITICAL` 反而是错的——会白白关中断影响别的任务。
- **队列用 `float` 而不是 `uint16_t`**：BH1750 的分辨率是 1 lx，`read_BH1750()` 返回的是 `raw/1.2`，小数部分有信息量（比如 12 lx vs 12.5 lx）；`uint16_t` 会把小数抹掉。如果你不在意，也可以改成 `uint16_t`，那上报时就是整数。

### 第 5 步：接进上报（可选，但要动云端）

现在 `APP/app_json.c` 只上报 Temp 和 Hum。要加光照，得改三处，**而且云端也得先加属性**：

1. **OneNET 控制台**：在设备的物模型里**新增一个属性**，比如标识符 `Lux`、数据类型 `int32`（或 `float`）。**这一步不做，后面发上去的报文会被云端丢掉**，表现是"数据发出去了但平台上看不到"。
2. `APP/app_json.c`：加 `AppJson_SetLux(int lux)`，并把 `s_Lux` 拼进 params（注意 `\"` 和 `\,` 的转义写法，照抄现有的 `\\\"Temp\\\"` 格式）。
3. `APP/task_wifi.c`：`xQueueReceive` 改成同时收两个队列，或者在光照任务里直接调上报。**推荐前者**——保持"只有 WiFi 任务碰 ESP8266"这条规矩，否则两个任务同时 `HAL_UART_Transmit` 会把 AT 指令撕碎。

⚠️ 光照值变化频繁（灯一开一跳就是几百 lx），会让 `AppJson_Report()` 的"值变化才发"几乎每次都成立，上报频率会比现在高很多。如果嫌费流量，在 `AppJson_SetLux()` 里做**量化**，比如 `lux / 10 * 10`，只上报到 10 lx 精度。

### 第 6 步：验证

按顺序来，每步过了再做下一步：

1. **编译**——先只加 `bh1750.c` 和那个 `BSP_DelayUs()`，不建任务，直接编译。过不了就是头文件路径或 `main.h` 的问题。
2. **单测微秒延时**——见第 0 步。这一步不过，后面全是玄学。
3. **裸测传感器**——在 `App_Init()` 里 `BH1750_Init()` 之后直接 `printf("lux=%d\r\n", (int)BH1750_ReadLux());`，先不建任务。**用手电筒照 / 拿手捂住**，数字必须在 0~54612 之间大幅变化。
4. **读失败的两副面孔**——如果不管怎么照都是 **54612**（= 65535/1.2），说明总线读回全 1：查 SCL/SDA 有没有接反、GY-302 有没有供电（`U6.1` 接 3V3）、PB6/PB7 是不是被别的初始化抢了。如果恒为 **0**，同样先查线。
5. **建任务**——打开第 2 步的任务，串口应该每 2 秒打一行 `[LIGHT] xxx lx`。
6. **看内存**——在 `TaskLight` 里调一次 `uxTaskGetStackHighWaterMark(NULL)` 打印出来，如果剩余小于 50 字就把 `APP_STACK_LIGHT` 加大；同时确认没进 `Error_Handler`（那是堆不够，要加 `configTOTAL_HEAP_SIZE`）。

### 怎么在 OLED 上看

如果你已经按 [02-OLED显示屏移植.md](02-OLED显示屏移植.md) 把屏点起来了，把光照显示加进去最省事：在 OLED 任务里 `OLED_ShowString(3, 1, "Lux:")` + `OLED_ShowNum(3, 6, (uint32_t)lux, 5)`。**注意显示和采集要解耦**——OLED 任务自己读一份全局变量（或者用队列里的最新值），别让 OLED 任务去直接调 `BH1750_ReadLux()`，否则屏一刷新就把 I2C 占着，采集周期会被拖长。
